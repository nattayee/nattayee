# Treatment Planning Management

ระบบกระจายงานฟิสิกส์การแพทย์ · กลุ่มงานรังสีรักษา โรงพยาบาลมะเร็งลำปาง

เว็บแอปหน้าเดียวสำหรับแจกเคสวางแผนการรักษาให้นักฟิสิกส์การแพทย์ตามคิวหมุนเวียน ติดตามงานค้าง บันทึก RC และสรุปแต้ม P4P รายเดือน
ทำตามโครงสร้างของไฟล์ `P4P_Physics` เดิม ข้อมูลเก็บใน Google Sheet ของทีมเอง

## ทำอะไรได้บ้าง

- **แจกเคสใหม่**: กรอก HN รายละเอียดผู้ป่วย แล้วเลือกเทคนิค เลือกได้หลายเทคนิคในครั้งเดียว
  ระบบสร้างเคสแยกให้แต่ละเทคนิค (ใช้ข้อมูลผู้ป่วยชุดเดียวกัน) และ**ให้นักฟิสิกส์คนเดียวกันทั้งหมด**
  - **เทคนิคแรกที่กดเลือก** แจกตามคิวของเทคนิคนั้น (ชิปที่มีกรอบสองชั้นคือเทคนิคแรก กดเลือกใหม่เพื่อเปลี่ยนได้)
  - **เทคนิคถัดไป** ให้คนเดียวกันโดยไม่สนลำดับคิวของเทคนิคนั้น และนับเป็นโควตาที่ได้ไปแล้ว คิวของเทคนิคนั้นไม่ขยับ
    แต่เมื่อคิววนมาถึงคนนั้นจะถูกข้าม 1 ครั้ง (เหมือนเคสเลือกเอง) เช่น VM H&N คิวอยู่ที่ NY และเลือก VM Chest ด้วย → NY ได้ทั้งสองเคส
    และคิว VM Chest จะข้าม NY หนึ่งรอบ
  - แต้มนับตามแต่ละเทคนิค · หน้าจอแสดงก่อนกดว่าจะไปที่ใครและหักคิวไหน เลือกวิธีแจกได้สองแบบ
  - **อัตโนมัติตามคิว**: ระบบเลือก MP ให้เอง และแสดงก่อนกด "แจกเคส" ว่าเคสจะไปที่ใคร ข้ามใครเพราะอะไร
  - **เลือกเอง**: เลือกผู้รับเคสเอง คิวไม่ขยับ แต่คนนั้นจะถูกข้าม 1 ครั้งเมื่อคิววนมาถึง (หักคิวให้เท่ากัน) ถ้าเลือกหลายเทคนิค จะหักในคิวของทุกเทคนิคนั้น
  - กด "เลิกทำ" ได้ถ้าแจกผิด ทุกเคสในชุดนั้นถูกลบ คิวกลับที่เดิม และข้อมูลกลับมาอยู่ในฟอร์ม
- **พื้นหลังแต่ละหัวข้อในฟอร์มแจกเคสและหน้าแก้ไขเคสสลับสองสี** (เทา / เขียวอ่อน · โหมดกลางคืนเป็นสีเข้ม) อ่านแยกหัวข้อง่าย
  บริเวณที่ฉาย + Dose + บริเวณเพิ่มเติม เป็นหัวข้อเดียว · หัวข้อที่ซ่อนอยู่ไม่นับ สีจึงสลับกันเสมอ
- **บริเวณที่ฉาย**: Head, H&N, Chest, Abdomen, Pelvis, Extremity เลือกได้หลายอย่าง และ "อื่นๆ" กรอกเองได้ (คั่นด้วยจุลภาค)
  เก็บเป็นข้อความเดียว เช่น `H&N, Chest, Spine` ค้นหาในรายการงานได้ · รายการบริเวณแก้/เพิ่มได้ในหน้าตั้งค่า
- **Diag (ICD-10)**: พิมพ์รหัส (C50) ชื่อไทย (เต้านม) หรือชื่ออังกฤษ (breast) แล้วเลือกจากรายการ
  มีรหัส ICD-10 หมวดเนื้องอก C00–C97 รหัสย่อยที่ใช้ในรังสีรักษาบ่อย (เช่น C50.x, C53.x, C34.x, C71.x, C79.3, C79.5) และ D/G/L/Q บางรหัส
  พิมพ์รหัสอื่นที่ไม่มีในรายการได้ และเพิ่มรหัสหรือชื่อที่หน่วยงานใช้เองได้ในหน้าตั้งค่า
- **ขนาดรังสี**: Dose/fx (Gy), จำนวน Fx (แสดงปริมาณรังสีรวมให้อัตโนมัติ) และความถี่ในการฉาย Daily, EOD, BID, Single fraction
  หรือ "อื่นๆ" กรอกเอง · เลือก Single fraction แล้ว Fx เป็น 1 ให้เอง · รายการความถี่แก้/เพิ่มได้ในหน้าตั้งค่า
- **คิวหมุนเวียนแยกตามเทคนิค** ตามลำดับทีม JR → WM → NY → WS เหมือนคอลัมน์ MP ที่เติมไว้ล่วงหน้าในแต่ละแท็บ
  ใครได้เคสแล้ว เคสถัดไปของเทคนิคนั้นจะวนไปคนต่อไป
  - **หักคิวรายเดือน** (ตั้งค่า → คิวหมุนเวียน แอดมินตั้ง): ตารางเทคนิค × นักฟิสิกส์ของแต่ละเดือน (‹ › เปลี่ยนเดือน)
    ใส่จำนวนครั้งที่ให้ข้ามคนนั้นในคิวของเทคนิคนั้น (1–20 เหมือนได้เคสนอกคิวไปแล้ว) · เริ่มนับตั้งแต่ต้นเดือนที่ตั้ง
    ใช้ไม่หมดยกไปเดือนถัดไป · ยอดที่ยังค้างดูที่ "รอหักคิว" · ตั้งเดือนหน้าไว้ล่วงหน้าได้ (ยังไม่มีผลจนถึงเดือนนั้น)
    ต้องใช้ Code.gs รุ่น 2026-10-12.5 ขึ้นไป (Code.gs เป็นคนแจกเคส รุ่นเก่ายังไม่มีตารางนี้)
- **วันลา**: กด "ลาวันนี้" ที่การ์ดของแต่ละคน หรือ "จัดการวันลา" เพื่อลงวันลาล่วงหน้าเป็นช่วงวัน
  คนที่ลาในวัน In ของเคสจะไม่ได้รับเคส ระบบข้ามไปคนถัดไปและไม่ทำให้ใครได้เคสซ้ำสองครั้งติด
- **ติดตามงานค้าง**: เรียงตามวัน Start RT พร้อมบอกว่าเหลืออีกกี่วันหรือเลยกำหนดมาแล้ว กดปุ่ม `Finish` หรือ `Evaluate` เพื่อลงวันที่เป็นวันนี้ทันที
- **RC (Quality Checklist)**: กด `+ RC` ที่เคส ระบบแนะนำคนที่ RC น้อยที่สุดเดือนนี้ (ไม่ใช่ผู้วางแผน) และบันทึก RC ที่ไม่ผูกกับเคสได้ เช่น RC Decay
- **RC และกิจกรรมเป็นการบันทึกงานที่ทำแล้ว** ไม่เกี่ยวกับคิวแจกงาน วันลาจึงไม่มีผล (เลือกใครก็ได้ ระบบไม่ข้ามและไม่เตือนเรื่องลา)
- **Brachytherapy และ Hyperthermia**: เป็นกิจกรรมนับครั้งในหน้า "RC และกิจกรรม" ไม่ได้แจกตามคิว
  - แถบ **Brachytherapy** รวม Brachy 3D และ Brachy เสียบเข็ม · แถบ **Hyperthermia** รวม Plan to heat และ Hyperthermia control
  - **บันทึก Brachytherapy หลายคนพร้อมกัน**: ในหน้าบันทึกกิจกรรม ปุ่ม **Brachytherapy** แทน Brachy 3D / Brachy เสียบเข็ม (กด "+ กิจกรรม" ในแถบ Brachytherapy ก็เปิดแบบนี้)
    ตารางคนละบรรทัด: **HN · นักฟิสิกส์ผู้วางแผน · นักฟิสิกส์ RC · ช่องติ๊กเสียบเข็ม** (พิมพ์บรรทัดสุดท้ายแล้วมีบรรทัดว่างเพิ่มเอง · Enter ไปบรรทัดถัดไป)
    ผู้วางแผนได้แต้ม Brachy 3D (ติ๊กเสียบเข็ม = Brachy เสียบเข็ม) · RC ได้แต้ม RC (ไม่มี RC เว้นว่างได้ · RC ต้องไม่ใช่คนเดียวกับผู้วางแผน)
    วันที่และ Note ใช้กับทุกบรรทัด · รายการ RC ขึ้นว่า "แผน Brachy 3D ของ WM" · แก้รายการที่บันทึกแล้วทีละรายการได้เหมือนเดิม
  - กด "+ กิจกรรมอื่น" ในแถบนั้น เลือกกิจกรรม MP วันที่ HN และชื่อผู้ป่วย แต้มนับตามจำนวนครั้ง × เวลา × น้ำหนัก
  - ในหน้าตั้งค่า (กิจกรรมนับครั้ง) แก้ชื่อ แถบ กลุ่มในแบบ P4P เวลา น้ำหนัก และเลือกว่าบันทึก HN หรือไม่ได้
    เพิ่มกิจกรรมใหม่เข้าแถบเดิมได้ หรือลบชื่อแถบเพื่อให้มีแถบของตัวเอง
  - เคส Brachy/Hyperthermia ที่บันทึกไว้แบบเดิม (แท็บ Cases) ย้ายไปเป็นกิจกรรมในแท็บ Logs ให้เองครั้งแรกที่เปิดระบบ แต้มเท่าเดิม
- **กิจกรรมอื่น**: Daily QA, งานวิชาการ, งานบริหาร (เวลา × k)
- **ตำแหน่ง**: เลือกตำแหน่งให้แต่ละคนในหน้าตั้งค่า ค่าเริ่มต้นมี "หัวหน้า" (แต้มตั้งต้น 360/เดือน) และ "นักฟิสิกส์การแพทย์" (0)
  แก้ชื่อ แต้มตั้งต้น แต้มประกัน หรือเพิ่มตำแหน่งได้ เปลี่ยนตำแหน่งของใครมีผลตั้งแต่เดือนนั้น เดือนก่อนหน้าคิดตามตำแหน่งเดิม
- **สรุป P4P**: ทุกคนเริ่มเดือนที่แต้มประกัน −1,200 (หัวหน้าเริ่มที่ −840 เพราะมีแต้มตั้งต้น 360) แล้วบวกแต้มที่ทำได้จนได้คะแนนรวม
  มีตารางเทียบทุกคน และ**ใบคะแนนรายคน**ที่แสดงยอดสะสมทีละกิจกรรมแบบแบบฟอร์ม P4P เดิม พร้อมสถิติเคสตาม Type / Aim แบบแท็บ Month
- **ดาวน์โหลด Excel** (ปุ่มในหน้าสรุป P4P): แบบจัดเก็บคะแนนภาระงาน (Activity base) ของเดือนที่เลือก แบบแท็บ P4P เดิม
  - เลือก "ทุกคน" = 1 แผ่นงานต่อคน · เลือกชื่อ = เฉพาะคนนั้น · ไฟล์ชื่อ `P4P-2569-10.xlsx` (หรือ `P4P-2569-10-JR.xlsx`)
  - คนละ 3 หน้า A4 แนวนอน: งานห้อง / 3D / IMRT · VMAT / Brachytherapy / Hyperthermia · งานวิชาการ / งานบริหาร + สรุปแต้ม
    (แต้มประกัน แต้มต่อ แต้มที่ทำได้ ส่วนต่างแต้ม) · เทคนิคหรือกิจกรรมที่เพิ่มเองอยู่ในกลุ่มของมัน กลุ่มที่ไม่พอหน้าขึ้นหน้าใหม่
  - จำนวนรายวัน 1–31 ตามวัน In ของเคส (เทคนิค + New MU ตามจำนวนครั้ง) และวันที่ของบันทึก RC / กิจกรรม · ไม่มี = "-"
    เสาร์–อาทิตย์และวันหยุดเป็นสีเขียว · งานวิชาการ/บริหาร บันทึกละแถว (เวลา × k × แต้มมาตรฐาน)
  - รวม ทำได้ แต้ม/หน่วย และสรุปแต้มเป็นสูตร แก้จำนวนในไฟล์แล้วคำนวณใหม่ · ตัวเลขตรงกับหน้าสรุป P4P
  - แถวในแบบฟอร์มที่ยังไม่ได้ใช้ (3D Brain tumor, กลุ่ม IMRT) ใส่ไว้ให้ครบ นับเป็น 0
  - หัวกระดาษใช้ชื่อ-สกุล และ "ตำแหน่งในแบบฟอร์ม" ของแต่ละคน (ตั้งค่า → ทีม · ไม่ใส่ = ใช้ชื่อตำแหน่งในระบบ)
    และ "กลุ่มที่" (ตั้งค่า → เทคนิคและน้ำหนัก P4P) · ฟอนต์ TH Sarabun PSK
  - สร้างไฟล์ในเบราว์เซอร์ด้วย ExcelJS (โหลดจาก cdnjs หรือ jsDelivr ตอนกดปุ่ม) ไม่ต้องอัปเดต Code.gs
- **ตั้งค่าได้ทุกหัวข้อ**: เพิ่ม/แก้ทีมและตำแหน่ง, เพิ่มเทคนิคใหม่ (ชื่อ, กลุ่มในแบบ P4P, ประเภท, เวลา, น้ำหนัก, รอบคิว, New MU, Technique),
  เพิ่มกิจกรรมนับครั้ง (เช่น Machine QA) ซึ่งจะเป็นตัวเลือกในหน้า RC และกิจกรรมและนับแต้มใน P4P,
  เพิ่ม/ลบตัวเลือก Type, Aim, Technique, ความถี่, บริเวณที่ฉาย · เทคนิคหรือกิจกรรมที่มีข้อมูลแล้วลบไม่ได้ (ปิด "แสดงในฟอร์ม" แทน)
- **แพทย์ (Doc)**: เพิ่ม/ลบ/เรียงลำดับได้แบบเดียวกับทีมนักฟิสิกส์ แต่ละคนมีรหัสและชื่อ-สกุล (ไม่บังคับ)
  ปุ่มในฟอร์มแสดงรหัส ชี้ที่รหัสเพื่อดูชื่อ และค้นหาเคสด้วยชื่อแพทย์ได้
- **สีของแพทย์และนักฟิสิกส์** (ตั้งค่า → แพทย์ / ทีมนักฟิสิกส์): ช่องเลือกสีหลังรหัส มีตัวอย่างป้ายให้ดู · × = แพทย์ไม่ใช้สี / นักฟิสิกส์กลับเป็นสีอัตโนมัติ
  ค่าเริ่มต้น SC น้ำเงิน · TA เขียว · PM ดำ · TC ส้ม · ป้ายแพทย์มีสีในตารางวันฉาย รายการเคส (การ์ด/บรรทัดเดียว) และแถบ Complete
  ป้าย MP ใช้สีที่ตั้งทุกที่ · ตัวอักษรเป็นขาวหรือดำตามความสว่างของสี · โหมดกลางคืนมีเส้นขอบให้ป้ายสีเข้มยังมองเห็น
- **ช่องบังคับกรอก**: เลือกได้ว่าช่องไหนในฟอร์มแจกเคสต้องกรอก (Name, Doc, Diag, บริเวณที่ฉาย, Type, Aim, Technique, Dose/fx, Fx,
  ความถี่, CT-Sim, Start RT, Note) ช่องที่บังคับมี * ในฟอร์ม และกด "แจกเคส" ไม่ได้จนกว่าจะกรอก
  HN และเทคนิคบังคับเสมอ · ช่องของงานวางแผน (Doc, Type, Aim, Technique, CT-Sim, Start RT) บังคับเฉพาะเมื่อเลือกเทคนิคที่เป็นงานวางแผน · "on call" นับว่ากรอก Start RT แล้ว
- **ค่าเริ่มต้นในฟอร์มแจกเคส** (ตั้งค่า → ค่าเริ่มต้นและช่องบังคับกรอก ตารางเดียวกับช่องบังคับ): แต่ละช่องเลือกค่าเริ่มต้นหรือ "ไม่มี" ได้
  Doc, เทคนิค, Type, Aim, ห้องฉาย, Technique, บริเวณที่ฉาย, Dose/fx, Fx, ความถี่, CT-Sim, Start RT, Note และหัวข้อเพิ่มเติม (ตั้งที่หัวข้อนั้น)
  - ฟอร์มใส่ค่าเริ่มต้นให้ตอนเปิด หลังแจกเคส และเมื่อกด "ล้างฟอร์ม" แก้หรือเอาออกในฟอร์มได้ (กดปุ่มที่เลือกอยู่ซ้ำ = เอาออก)
  - วันที่ตั้งเป็นจำนวนวันทำการนับจากวันแจก (0 = วันแจก, −1 = วันทำการก่อนหน้า) ข้ามเสาร์–อาทิตย์และวันหยุด · Start RT ตั้งเป็น on call ได้
  - เทคนิคและบริเวณที่ฉาย (เลือกได้หลายอย่าง): กดเลือกอย่างอื่นครั้งแรกจะเปลี่ยนแทนค่าเริ่มต้น ไม่แจกเป็น 2 เทคนิคโดยไม่ตั้งใจ
  - ตั้ง Dose/fx และ Fx ไว้ทั้งคู่: กรอก Prescription แล้ว Fx คำนวณใหม่ (Dose/fx คงไว้) · ความถี่ Single fraction ที่ไม่ได้ตั้ง Fx ใส่ Fx 1
  - แก้ค่าเริ่มต้นแล้ว ฟอร์มที่ยังไม่ได้กรอกเปลี่ยนตามทันที ฟอร์มที่กำลังกรอกอยู่ไม่ถูกทับ · ตัวเลือกที่ถูกลบไปแล้วไม่ใช้เป็นค่าเริ่มต้น
  - เริ่มต้นตั้งไว้ Type = New เหมือนเดิม · ไม่ต้องอัปเดต Code.gs
- **ค่าเริ่มต้นตามเทคนิค, Type หรือ ICD-10** (ตารางถัดไปในส่วนเดียวกัน): แต่ละแถวเลือกเงื่อนไข เทคนิค / Technique / Type / ICD-10
  แล้วตั้ง Dose/fx, Fx, ความถี่, ห้องฉาย, บริเวณที่ฉาย, Aim (แสดง Prescription ที่ได้ให้ดู)
  - เช่น เทคนิค VM H&N → ห้องฉาย Infinity และบริเวณ H&N · Type Emer high → Aim Palliative · Type New → Aim Curative
  - เลือกเทคนิค, Technique, Type หรือ Diag ที่ตรงในฟอร์มแล้วใส่ค่าให้ทันที เปลี่ยนแล้วเปลี่ยนตาม
    เฉพาะช่องที่ยังไม่ได้แก้เอง (แก้ Dose/fx, Fx หรือกรอก Prescription เองแล้ว Dose/fx กับ Fx ไม่เปลี่ยนอีก · เลือกห้อง บริเวณ หรือ Aim เองแล้วไม่ทับ)
  - บริเวณที่ฉายที่ระบบใส่ให้: กดเลือกบริเวณอื่นครั้งแรกจะเปลี่ยนแทน ไม่เพิ่มต่อ
  - ตรงหลายแถว: Technique ก่อน แล้วเทคนิคแรกที่เลือก แล้ว Type แล้ว ICD-10 (รหัสยาวกว่าก่อน) แล้วค่าเริ่มต้นทั่วไป
    Dose/fx กับ Fx มาคู่กันจากแถวเดียว ไม่ปนกันระหว่างแถว
  - ICD-10 ใส่รหัสหรือต้นรหัส เช่น C61 หรือ C50 (ตรงกับ C50.0–C50.9)
  - ตั้งไว้ให้แล้ว: 3D Breast และ VM Breast 16 fx · Technique SRS 1 fx (SBRT/CSI ไม่ใช่) · ICD-10 C61 (Prostate) 2.5 Gy × 28 fx = 70 Gy
  - Type → Aim ตั้งไว้ให้จากไฟล์ P4P เดิม (Aim ที่ใช้บ่อยที่สุดของแต่ละ Type): New → Curative · Emer low, Emer high → Palliative
    · Replan, Adap → On tx · CP → Curative (มี 1 เคส) · การตั้งค่าที่บันทึกไว้ก่อนแล้วได้แถวเหล่านี้เพิ่มครั้งเดียว
    · ไฟล์เดิมไม่มีห้องฉายและบริเวณที่ฉาย จึงยังไม่มีกฎของเทคนิค
    แก้หรือลบได้ ลบหมดแล้วไม่กลับมาเอง
- **เต็มจอกว้าง**: หน้าเว็บกว้างได้ถึงราว 1,700 px (จอใหญ่กว่านั้นอยู่กลางจอ) · จอกว้างพอ โลโก้ แถบเมนู และผู้ใช้อยู่แถวเดียวกัน · การ์ดภาระงานทีมยืดเต็มแถว
- **แถบด้านบนตรึงไว้**: เลื่อนหน้าลงแล้วโลโก้และชื่อระบบเลื่อนพ้นไป แถว Home · ค้นหา · โหมดกลางวัน/กลางคืน · แถบเมนู · ผู้ใช้ ค้างอยู่ขอบบนเสมอ (มีเส้นใต้)
  มือถือค้างตั้งแต่แถวแถบเมนูลงมา · ขนาดแถบไม่เปลี่ยน หน้าจึงไม่กระตุกตอนเลื่อน
- **ค้นหาเคส** (แว่นขยายมุมขวาบน หรือกด `/`): ค้นหาทุกเคส ทั้งที่ค้าง เสร็จแล้ว Complete course และ Cancel RT
  พิมพ์ HN ชื่อ แพทย์ Diag บริเวณ ห้อง หรือรหัส MP (หลายคำ = ต้องตรงทุกคำ) · ผลแสดงสถานะของแต่ละเคส · Enter หรือกดผล = เปิดหน้าแก้ไขเคส
  (ตำแหน่งอื่นไปที่หน้างานพร้อมค้นหา HN นั้น) · Esc ปิด
- **ช่องค้นหาในแต่ละแถบ** (งาน · งานรอ · ตารางแจกเคส · ห้องฉาย · RC และกิจกรรม): กรองเฉพาะรายการในแถบนั้นทันที **ไม่ไปแถบอื่น**
  หลายคำ = ต้องตรงทุกคำ · ไม่สนตัวพิมพ์เล็ก/ใหญ่ · Esc ล้าง · จำคำค้นไว้ตอนสลับแถบ (หายเมื่อโหลดหน้าใหม่) · ช่องที่มีคำค้นเป็นสีเขียว
  - งานรอ: ตัวเลขบนการ์ดนับเฉพาะเคสที่ตรง · ยังไม่เลือกการ์ด = แสดงเคสที่ตรงจากทุกขั้นตอน
  - ห้องฉาย: ค้นหา HN ชื่อ แพทย์ MP รายละเอียดผู้ป่วย ฯลฯ · ตัวเลขบนแท็บย่อย (กำลังฉาย / Complete course / Cancel RT / Off RT) บอกว่าเจอที่แท็บไหน
    ใช้ร่วมกับตัวกรองที่หัวคอลัมน์และปุ่มเลือกห้องได้
  - ตารางแจกเคส: เฉพาะเทคนิคและเดือนที่เลือก · แท็บเทคนิคบอกจำนวนเคสที่ตรงในเดือนนั้น
  - RC และกิจกรรม: เฉพาะเดือนที่เลือก (HN ชื่อ MP ชื่อกิจกรรม หมายเหตุ) · ตัวเลขบนแท็บนับตามคำค้น
  - แดชบอร์ดและสรุป P4P เป็นหน้าสรุปตัวเลข จึงไม่มีช่องค้นหา
- **แถบ CT-SIM** (ต้องใช้ Code.gs รุ่น 2026-10-24.1 ขึ้นไป): บันทึกผู้ป่วยที่ทำ CT จำลองการฉาย แยกเครื่อง **CT-1 (30)** และ **CT-2 (32)** (แก้ชื่อ/เพิ่มเครื่องได้ที่ ตั้งค่า → CT-SIM)
  - ตารางรายเดือนแบบไฟล์ CT-SIM เดิม แยกตามวัน (วันล่าสุดก่อน): No. · N/D (ลำดับในวัน) · HN · Name · Organ · Mask · bitelock · CM · Coil · Y · Syring Injector · Normal Saline · Syring 50cc · แพทย์ · สถานะ · HDR · C-RAD · Note · เคสวิจัย · เทคนิค · สถานะในแถบงาน
    ‹ › เปลี่ยนเดือน · ช่องค้นหา · คอลัมน์ของช่องที่ตั้งไม่แสดงถูกซ่อน · กดแถวเพื่อแก้
  - **"+ เพิ่มผู้ป่วย"**: เครื่อง CT วันที่ HN (บังคับเสมอ) + ช่องแบบฟอร์มแจกเคส (Name, Diag, แพทย์, เทคนิค, Type, Aim, ห้องฉาย, Technique, บริเวณที่ฉาย, Dose/Fx, Start RT, หัวข้อเพิ่มเติม)
    \+ ช่องห้อง CT (Organ, Mask, CM, Coil, Y, Syring Injector, Normal Saline, Syring 50cc เลือก 1–4, สถานะ, HDR, Bitelock, C-RAD, เคสวิจัย, Note)
    - ตั้งค่า → CT-SIM → ฟอร์มเพิ่มผู้ป่วย: แต่ละช่อง ไม่แสดง / แสดง / บังคับกรอก (ค่าเริ่มต้น: แพทย์และ Organ บังคับ · Diag, Type, Aim, ห้องฉาย, Technique, บริเวณ, Dose, Start RT ไม่แสดง)
    - ตัวเลือกของ Organ, Mask, CM, สถานะ, HDR แก้ได้ที่ ตั้งค่า → CT-SIM · แพทย์ใช้รายชื่อ แพทย์ (Doc)
    - **"ส่งไปแถบงาน"** (ติ๊กไว้ให้): บันทึกแล้วขึ้นในแถบงานให้ MP ดึงไปแจกเคส · ยืนยันด้วยรหัส PIN (ตั้งค่า → รหัส PIN: CT-SIM)
  - **ผู้ปฏิบัติงานประจำวัน** (ใต้วันที่ในตาราง): นักรังสีการแพทย์ (RTT), ผู้ช่วย (RA) และคนทำ **Daily QC** ของเครื่องนั้น
    เลือกจากสมาชิก LPCH RO Workspace (ตำแหน่งตามที่ตั้งใน ตั้งค่า → ตารางวันฉาย) + พิมพ์ชื่อเอง · คัดลอกจากวันทำการก่อนหน้า · ใช้ในแผ่น Competency ของไฟล์ส่งออก
  - **"ส่งออก Excel"**: ไฟล์ของเครื่องที่เลือก เดือนที่แสดง ชื่อแบบเดิม (เช่น `CT-SIM1-10_69.xlsx`) มี 3 แผ่นแบบไฟล์ตัวอย่าง
    - **CT-SIM**: ข้อมูลรายคน (No. เป็นสูตร · Date · N/D ...) พร้อมช่องเลือก (dropdown) แบบเดิม ไฮไลต์วันนี้ · จำนวนเคสวิจัย
    - **SUM**: เคสรวมต่อแพทย์ · HDR ต่อแพทย์ · HDRซ้ำ · CT (= รวม − HDR) · อุปกรณ์ที่ใช้เดือนนี้ (Mask, CM, Bitelock, Coil, Y, NSS, Syringe, reuse) พร้อมช่องรับมา/รับเพิ่ม/คงเหลือ
    - **Competency**: วันที่ 1–31 ของเดือน · งานรายวัน (Daily QC, จัดเตรียม, ทำความสะอาด, ไม่ฉีด/ฉีดสารทึบรังสี, เปลนั่ง, เปลนอน/HDR, Gating (C-RAD), Immobilize) · Tech 1–5, ผู้ช่วย 1–2, QC จากผู้ปฏิบัติงาน
    - SUM และ Competency เป็น**สูตรที่อ้างข้อมูลในแผ่น CT-SIM** (แก้หรือเพิ่มแถวในไฟล์แล้วตัวเลขเปลี่ยนตาม) · แพทย์แสดงชื่อจากตั้งค่า (ไม่มีชื่อ = รหัส)
  - **แถบงาน → "ดึงจาก CT-SIM (n)"** (หัวกล่องแจกเคสใหม่): รายการที่ห้อง CT ส่งมาและยังไม่แจก (เก่าสุดก่อน)
    - **ใช้ข้อมูลนี้** = ใส่ลงฟอร์มแจกเคส (HN, Name, CT-Sim = วันที่ทำ CT, แพทย์, เทคนิค, บริเวณที่ฉาย (Organ ที่ตรงกับตัวเลือก), Dose, Start RT, Note ฯลฯ) ตรวจแล้วกดแจกเคส
      แจกแล้วรายการผูกกับเคส (แถบ CT-SIM แสดง "แจกแล้ว · MP") · กดเลิกทำ = กลับเป็นรอแจก
    - **ไม่ต้องแจก** = เอาออกจากรายการ (คืนกลับได้ในหัวข้อ "ไม่ต้องแจก")
  - สิทธิ์: ตั้งที่ ตั้งค่า → แถบเมนู (แถว CT-SIM) เช่น RTT บันทึกได้ · ดึงไปแจกเคสต้องบันทึกได้ในแถบงาน
  - เก็บในแท็บ `CTSim` ของชีต (ผู้ปฏิบัติงานอยู่ในแท็บ `Duty` ห้อง `CT:<รหัสเครื่อง>`) · ส่งให้หน้าเว็บย้อนหลังประมาณ 13 เดือน
- **แถบ Complete**: แยก กำลังฉาย / รอฉาย · Complete course · Cancel RT · Off RT (เลือกห้องฉายได้)
  - **กำลังฉาย / รอฉาย = ตารางวันฉาย**: วันที่อยู่หัวตาราง (คอลัมน์แรกคือวันนี้ ข้ามเสาร์–อาทิตย์ วันหยุดเป็นลายขีด)
  - **เห็นผู้ป่วยตั้งแต่ลง CT-SIM**: รายการในแถบ CT-SIM ที่ติ๊ก "ส่งแถบงาน" (ยังไม่แจก · ไม่นับรายการที่ตั้งไม่ต้องแจก) และเคสที่แจกแล้วแต่ยังไม่ Plan complete
    ขึ้นเป็นแถว **"รอ Plan complete"**: เห็นวันฉายตาม Start RT / Fx / ความถี่ (ช่องโปร่ง กรอบเทา) แต่**กดบันทึกสถานะ fraction ไม่ได้จนกว่า MP กด Plan complete**
    - ใต้วันที่นับรวมในจำนวนทั้งหมด และแสดงแยกเป็น "+n" ต่อท้าย ฉายแล้ว/Hold/ค้างบันทึก · ตัวกรองสถานะมี "รอ Plan complete"
    - แถวจาก CT-SIM (ยังไม่มีเคส): ชี้ค้างที่ HN เห็นเครื่อง CT วันที่ CT · บันทึก Mosaiq Time / รายละเอียดผู้ป่วยไม่ได้ · MP แจกเคสแล้วแถวเปลี่ยนเป็นของเคส (กด HN แก้ไขเคสได้)
    - ผู้ป่วยที่มีเคส Plan complete แล้ว: แถวใช้ตารางของเคสนั้น บันทึกสถานะ fraction เฉพาะเคสที่ Plan complete
    - ไม่นับเคสค้างเก่า (Start RT เลยมาเกิน 14 วัน · ไม่มี Start RT และแจกมาเกิน 60 วัน · รายการ CT-SIM เกิน 60 วัน) · Code.gs รุ่นที่ยังไม่มีปุ่ม Plan complete ใช้ Evaluate แทน
    ใต้วันที่: บรรทัดบน = **ผู้ป่วยทั้งหมดของวันนั้น** (มี fraction หรืออยู่ในช่วง Hold ฯลฯ) · บรรทัดล่าง = **ฉายแล้ว** (เขียว: บันทึกฉายแล้ว
    หรือสถานะแบบฉายตามปกติ) / **Hold, HV, Re-CT ฯลฯ** (เหลือง) / **ค้างบันทึก** (แดง: ยังไม่ได้บันทึก) รวมกันเท่าบรรทัดบน · ชี้ค้างที่วันที่เห็นตัวเลขเต็ม
    **จำนวนผู้ป่วยเกินกำหนด = วงสีแดง** (ค่าเริ่มต้นเกิน 40 คน · ตั้งค่า → ตารางวันฉาย: ทุกห้อง และรายห้อง ว่าง = ใช้ค่าทุกห้อง · ว่างทั้งหมด = ไม่ใช้สี)
    นับตามห้องที่เลือกและตัวกรองที่ใช้อยู่ (เหมือนตัวเลข) · ใช้ได้เลยไม่ต้องวาง Code.gs ใหม่
  - **ผู้ปฏิบัติงานประจำวัน (RTT / RA)** ใต้จำนวนผู้ป่วยของแต่ละวัน: "RTT 2 · RA 1" (ชี้ค้างเห็นชื่อ) · ยังไม่เลือก = "+ RTT/RA" (วันนี้) / "+" (วันอื่น)
    - กดแล้วเลือก**นักรังสีการแพทย์ (RTT)** และ**ผู้ช่วย (RA)** แยกตามห้องฉาย (เลือกห้องไว้ = เฉพาะห้องนั้น · ทุกห้อง = ทุกห้องในหน้าเดียว) ติ๊กได้หลายคน

    - LPCH ไม่ให้ดึงรายชื่อด้วยบัญชีนั้น (หรือเปิดจากเมนูในชีต): ใช้รายชื่อล่าสุดที่เคยดึงได้ (ระบบจำไว้ทุกครั้งที่ดึงได้ รวมถึงตอนแอดมินดึงสมาชิกที่ ตั้งค่า → แถบเมนู) และพิมพ์ชื่อเองได้
    - บรรทัดเหนือตาราง: ชื่อผู้ปฏิบัติงานของวันนี้ (หรือวันแรกที่แสดง) แยกห้อง · กดเพื่อแก้ได้
    - เก็บในแท็บ `Duty` (วันที่, ห้องฉาย, RTT, RA เป็นชื่อคั่นด้วยจุลภาค, คนบันทึก, เวลา) · ส่งให้หน้าเว็บย้อนหลัง 1 ปี · ต้องใช้ Code.gs รุ่น 2026-10-22.2 ขึ้นไป
  - **ปุ่ม "+ เพิ่มผู้ป่วย"** (แถบนี้ สำหรับ RTT, RA, MP ที่บันทึกในแถบนี้ได้ · แอดมินเปิดสิทธิ์ที่ ตั้งค่า → แถบเมนู): บันทึกผู้ป่วยเข้าตารางวันฉาย**โดยไม่แจกงานให้ MP**
    - ฟอร์มแบบหน้าแก้ไขเคส (เทคนิค, HN, Name, Doc, ห้องฉาย, บริเวณที่ฉาย, Dose/fx, Fx, ความถี่, บริเวณเพิ่มเติม/boost, Start RT, Note ฯลฯ) ไม่มี MP ขั้นตอน และแต้ม
    - **ตั้งค่า → ตารางวันฉาย → ฟอร์มเพิ่มผู้ป่วย**: แต่ละช่อง ไม่แสดง / แสดง / บังคับกรอก (ค่าเริ่มต้น: ห้องฉาย, Dose/fx + Fx, Start RT บังคับ · CT-Sim, Type, Aim, Diag, หัวข้อเพิ่มเติม ไม่แสดง)
      HN และเทคนิคบังคับเสมอ · ต้องมี Start RT และ Fx จึงคำนวณวันฉายได้
    - ขึ้นในตารางวันฉายทันที (ไม่ต้อง Plan complete) HN มีกรอบเส้นประ · บันทึกสถานะ fraction, Mosaiq Time, รายละเอียดผู้ป่วยได้เหมือนเคสอื่น · นับในจำนวนผู้ป่วยของวัน
    - **ไม่อยู่ใน** งาน งานรอ ตารางแจกเคส คิว แต้ม P4P และสถิติการวางแผน (แดชบอร์ดนับเฉพาะวันฉาย) · ค้นหาด้วยแว่นขยายเจอ (สถานะ "เพิ่มในตารางวันฉาย")
    - กด HN เพื่อแก้หรือลบ (ยืนยันด้วยรหัส PIN · ตั้งค่า → รหัส PIN: เพิ่มผู้ป่วย) · Code.gs แก้/ลบได้เฉพาะผู้ป่วยที่เพิ่มทางนี้ (วิธีแจก `direct`) · ต้องใช้ Code.gs รุ่น 2026-10-22.2 ขึ้นไป
    **ผู้ป่วยละบรรทัด** (HN เดียวกันหลายเทคนิครวมเป็นแถวเดียว)
    ช่องแสดง **เลข fraction** ที่ฉายวันนั้น (คำนวณจาก Start RT, Fx, ความถี่ และบริเวณเพิ่มเติม · BID = "3–4" · Sequential boost นับต่อและมีขีดสีส้ม)
    เขียวเข้ม ✓ = บันทึกฉายแล้ว · เขียวอ่อน = ผ่านมาแล้ว (ยังไม่บันทึก) · กรอบ = วันนี้
    คอลัมน์ซ้าย (บรรทัดเดียว): Mosaiq Time · HN (กดแก้ไขเคส · ชี้ค้างดูเทคนิค แพทย์ MP ห้อง ขนาดรังสี วันครบ) · รหัสแพทย์ (ก่อน) และนักฟิสิกส์ · รายละเอียดผู้ป่วย
    · fx ที่ผ่านมา/ทั้งหมด (ไม่มีปุ่ม Complete / Cancel ในแถว: บันทึกผ่าน Off RT ในหน้าต่างสถานะ fraction · แถวที่ไม่มีวันฉาย กดป้าย "ไม่มีวันฉาย")
    จำนวนคอลัมน์พอดีความกว้างจอ (ไม่ต้องเลื่อนซ้ายขวา) · ‹ › เลื่อนทีละสัปดาห์ · "วันนี้" กลับมา
    เลื่อนลงแล้วส่วนบนค้างไว้ทั้งหมด: แถบด้านบน (ชื่อระบบ แถบเมนู) แท็บและห้อง คำอธิบาย ช่วงวันที่ และหัวตาราง (จอคอมพิวเตอร์ที่ส่วนนี้สูงไม่เกิน 60% ของจอ)
    มือถือหรือจอเตี้ย: ค้างเฉพาะแถบเมนูและหัวตาราง · แท็บ Complete course / Cancel RT / Off RT และหน้าอื่นเลื่อนตามปกติ
  - **ตัวกรองผู้ป่วย** (ปุ่มที่หัวคอลัมน์ผู้ป่วย): **Mosaiq Time · คิว · BD · แพทย์ · ฟิสิกส์ · เทคนิค · รายละเอียด · สถานะ** (รอฉาย / กำลังฉาย / Hold, HV, Re-CT ฯลฯ / ไม่มีวันฉาย)
    กดแล้วติ๊กค่าที่จะดู พร้อมจำนวนผู้ป่วยของแต่ละค่า · "แสดงทั้งหมด" ยกเลิกตัวกรองนั้น · ปุ่ม "ล้าง" ยกเลิกทุกตัวกรอง
    ผู้ป่วยที่มีหลายเคสแสดงเมื่อมีค่าใดค่าหนึ่งที่เลือก · หลายตัวกรองพร้อมกัน = ต้องตรงทุกตัว · ใช้ร่วมกับปุ่มเลือกห้องได้
    หัวคอลัมน์บอก "x จาก y คน" และจำนวนใต้วันที่นับเฉพาะผู้ป่วยที่แสดง · จำตัวกรองไว้จนกว่าจะโหลดหน้าใหม่
  - **รายละเอียดผู้ป่วยหลัง HN** (เช่น NPO, BD protocol, Empty BD): กด "+ บันทึก" หรือป้ายที่มีอยู่ → ติ๊กเลือกได้หลายอย่าง + ช่องพิมพ์เอง (คั่นด้วยจุลภาค)
    ใส่รหัส PIN · ติ๊กออกหมด = ล้าง · แอดมินเพิ่มตัวเลือกได้ที่ ตั้งค่า → สถานะ fraction · ค้นหาด้วยแว่นขยายได้
    เก็บในคอลัมน์ `รายละเอียดผู้ป่วย` ของแท็บ Cases (หน้าแก้ไขเคสลบไม่ได้) · ต้องใช้ Code.gs รุ่น 2026-10-18.1 ขึ้นไป
    - **คิว** (หน้าต่างเดียวกัน ด้านบน): ไม่ระบุ · **เช้า 1** · **เช้า 2** · **บ่าย** · **เย็น** → พื้นหลังของ HN ในตารางวันฉาย
      สีเริ่มต้น เช้า 1 เขียว · เช้า 2 ฟ้า · บ่าย ชมพู · เย็น เหลือง (โหมดมืดเป็นสีเข้มของสีเดียวกัน) · แถบ Complete course ฯลฯ แสดงเป็นป้าย "คิว …" สีเดียวกัน
      **แอดมินตั้งสีเองได้** ที่ ตั้งค่า → สถานะ fraction → "สีคิว": กดช่องสีของแต่ละคิว (เห็นตัวอย่างทันที) แล้วบันทึกการตั้งค่า
      สีที่ตั้งเองใช้เหมือนกันทั้งโหมดสว่างและมืด ตัวอักษรเป็นขาวหรือดำตามความสว่างของสี · กด × = กลับเป็นสีเริ่มต้น
    - **เวลา BD protocol**: ติ๊ก BD protocol แล้วมีช่องเลือกเวลา 08:00–17:00 ทุก 10 นาที (หรือไม่ระบุเวลา) · เลือกแล้วแสดง "BD 08:30" ต่อจากรหัสแพทย์และ MP
      ป้ายรายละเอียดยังแสดง "BD protocol" · ชี้ค้างที่ HN เห็นคิวและเวลา BD · มือถือซ่อนเวลา BD (ดูได้จากการชี้ค้าง/หน้าต่าง)
      ตัวเลือกที่ใส่เวลาได้ = ชื่อขึ้นต้น BD หรือ Bladder และมีคำว่า protocol (แอดมินเปลี่ยนชื่อเป็น Bladder protocol ได้)
    - ตัวกรอง **คิว** และ **BD** ที่หัวคอลัมน์ผู้ป่วย: เลือกค่าที่แสดง และ "เรียง เช้า→เย็น" / "เย็น→เช้า" (ไม่ระบุคิว / ไม่มีเวลา BD อยู่ท้ายเสมอ)
      ตัวกรองรายละเอียดไม่รวมคิว และนับ BD protocol เป็นค่าเดียวไม่ว่าเวลาไหน
    - คิวและเวลา BD เก็บรวมในคอลัมน์ `รายละเอียดผู้ป่วย` เป็นข้อความ เช่น "NPO, BD protocol 08:30, คิว เช้า 1" (อ่านในชีตได้) · ไม่ต้องวาง Code.gs ใหม่
  - **Mosaiq Time** (ช่องหน้า HN ไม่มีหัวคอลัมน์): พิมพ์เวลานัด เช่น 0830, 830, 8.30 หรือ 08:30 (เก็บเป็น 08:30 · พิมพ์ 8 = 08:00)
    กด Enter หรือออกจากช่อง → ใส่รหัส PIN → บันทึก · กด Enter แล้วไปช่องของผู้ป่วยถัดไปเลย กรอกต่อกันได้ · Esc หรือยกเลิกหน้าต่าง PIN = กลับเป็นค่าเดิม
    ลบให้ว่างแล้วออกจากช่อง = ล้าง · ผู้ป่วยหลายเทคนิคบันทึกให้ทุกเคส · ค่าที่พิมพ์ไม่หายตอนหน้าโหลดข้อมูลใหม่ (ทุก 1 นาที)
    ตำแหน่งที่ดูอย่างเดียวเห็นเวลาแต่ไม่มีช่องกรอก · เก็บในคอลัมน์ `Mosaiq Time` ของแท็บ Cases (หน้าแก้ไขเคสลบไม่ได้)
    ต้องใช้ Code.gs รุ่น 2026-10-19.2 ขึ้นไป (รุ่นเก่ามีช่องแต่บันทึกไม่ได้ ขึ้นข้อความให้อัปเดต)
    - **เรียงตามเวลา**: ปุ่ม "Mosaiq Time" (ปุ่มแรกที่หัวคอลัมน์ผู้ป่วย) → "เรียง เช้า→เย็น" หรือ "เย็น→เช้า" (กดซ้ำ = เลิกเรียง กลับไปเรียงตาม Start RT)
      ผู้ป่วยที่ยังไม่กรอกอยู่ท้ายเสมอ · ปุ่มมี ▲/▼ บอกว่าเรียงอยู่ · "ล้าง" ยกเลิกทั้งการเรียงและตัวกรอง · จำไว้จนกว่าจะโหลดหน้าใหม่
      ติ๊กเลือกเวลาที่แสดงได้ (เช่น เอา "(ยังไม่กรอก)" ออก หรือดูเฉพาะผู้ป่วยที่ยังไม่กรอกเพื่อกรอกต่อกัน)
      เรียงอยู่แล้วบันทึกเวลา: แถวย้ายไปตามเวลา แต่ Enter ยังไปช่องของผู้ป่วยที่อยู่ถัดลงมาก่อนบันทึก
  - **กดช่อง fraction เพื่อบันทึกสถานะ** (ยืนยันด้วยรหัส PIN บันทึกคนกดและเวลา · หนึ่งสถานะต่อวัน · ผู้ป่วยหลายเทคนิคบันทึกให้ทุกเคส):
    - **ฉายแล้ว**: วันนี้หรือวันที่ผ่านมาแล้ว เลือกไว้ให้ ใส่รหัส PIN ครบ 4 หลักแล้วบันทึกเลย · ช่องเป็นเขียวเข้มมี ✓ · บันทึกล่วงหน้าไม่ได้ (ต้องใช้ Code.gs 2026-10-18.1)
    - **Hold** · **HV** (home visit) · **Re-CT** (เลือกเหตุผล Adaptive / Tumor change / Re-position ต้องเลือก) = วันนั้นไม่ได้ฉาย fraction เลื่อนออกไปให้เอง
      ใส่ "กลับมาฉายวันที่" ได้ (ปุ่มลัด วันทำการถัดไป) · เว้นว่าง = **จนกว่าจะกลับมา**: ช่องถัดไปเป็นลายขีด fraction ที่เหลือรอไว้ แถวบอก "Hold … · เหลือ n fx"
      วันที่ผู้ป่วยกลับมา กดช่องลายขีด → ปุ่ม "กลับมา <วันนั้น>" แล้วบันทึก fraction ที่เหลือลงวันต่อจากนั้น
    - **Off RT** ต้องเลือก "หยุดฉายแบบ": **Complete course** = ฉายครบ fraction นั้นเป็นครั้งสุดท้าย (หมายเหตุไม่บังคับ)
      · **Cancel RT** = ไม่ได้ฉายตั้งแต่วันนั้น (**สาเหตุ บังคับ**) · บันทึกสถานะการฉายของเคส ทุกเทคนิคของผู้ป่วย เคสย้ายไปแถบนั้น หน้ายังอยู่ที่ตารางวันฉาย
      Off RT แบบเดิมที่บันทึกไว้แล้วยังอยู่แถบ **Off RT**: กดสถานะเพื่อ "ล้างสถานะ" (กลับเข้าตาราง) หรือเปลี่ยนเป็น Complete course / Cancel RT
    - **ย้ายห้อง** (มีในตัว เมื่อมีห้องอื่นให้ย้าย): เลือก **ย้าย** (เฉพาะ fraction นี้ วันถัดไปกลับห้องเดิม) หรือ **ย้ายตลอดไป** (ตั้งแต่ fraction นี้เป็นต้นไป) แล้วเลือกห้อง
      - ห้องเดิม (เลือกห้องนั้นไว้): ช่องแสดง **"ย้าย"** (เลข fraction ขีดฆ่า) นับเป็นสถานะอื่น (เหลือง) ใต้วันที่ · กดช่องนั้นเพื่อแก้หรือ "ล้างการย้ายห้อง"
      - ห้องใหม่: ผู้ป่วยอยู่ในรายชื่อของห้องนั้น fraction ที่ย้ายมาเป็นช่องปกติ บันทึกฉายแล้ว Hold ฯลฯ ได้เหมือนเคสของห้องนั้น นับในจำนวนของห้องนั้น
      - ทุกห้อง: ช่องที่ฉายห้องอื่นมีจุดสีส้ม ชี้ค้างเห็น "ย้ายมาจาก …" · แดชบอร์ดนับในห้องที่ฉายจริง · ย้ายตลอดไปครั้งหลังแทนครั้งก่อน (เช่นย้ายกลับ)
      - เก็บในคอลัมน์ `ย้ายห้อง` (JSON) แยกจากสถานะ fraction · หน้าแก้ไขเคสลบไม่ได้ · ต้องใช้ Code.gs รุ่น 2026-10-18.4 ขึ้นไป
    - **เพิ่ม fraction** (มีในตัว เฉพาะ **fraction สุดท้าย** ของคอร์ส): เลือกจำนวน **1–10** และใส่ **เหตุผล (บังคับ)** · ใส่ PIN
      - fraction ที่เพิ่มฉายต่อจากวันสุดท้ายตามความถี่เดิม (ข้ามเสาร์–อาทิตย์และวันหยุด) เลขต่อจากเดิม (คอร์สที่จบด้วย Sequential boost = ต่อเลข boost)
      - หน้าต่างบอกล่วงหน้า "รวม n fx · ครบ <วันที่>" · ช่องที่เพิ่มมีกรอบเส้นประ · ช่องที่บันทึกเพิ่มมี +n มุมขวาบน ชี้ค้างเห็นจำนวน เหตุผล คนบันทึก
      - fraction สุดท้ายใหม่เพิ่มต่อได้อีก · แก้หรือ "ล้างการเพิ่ม fraction" ได้ที่ช่องเดิม (ช่องที่มี +n) · วันนั้นยังบันทึกฉายแล้ว ฯลฯ ได้ตามปกติ
      - ผู้ป่วยหลายเทคนิค: เพิ่มให้ทุกเคสที่จบวันเดียวกัน · จำนวน fx รวมในแถว (ผ่านมาแล้ว/ทั้งหมด) และแถบ Complete course นับรวมที่เพิ่มแล้ว
      - เก็บในคอลัมน์ `เพิ่ม fraction` (JSON) ของแท็บ Cases · หน้าแก้ไขเคสลบไม่ได้ · ต้องใช้ Code.gs รุ่น 2026-10-21.1 ขึ้นไป (รุ่นเก่าไม่มีตัวเลือกนี้)
    - **งานวางแผนใหม่ให้ MP คนเดิม (อัตโนมัติ)**: บันทึก **Re-CT** (ทุกเหตุผล) หรือ **ย้ายห้อง** แล้วระบบสร้างเคสใหม่ให้ MP ของเคสนั้นทันที
      - ข้อมูลผู้ป่วย เทคนิค แพทย์ เหมือนเคสเดิม · **prescription = fraction ที่ยังไม่ได้ฉายตั้งแต่วันนั้น** (เช่น Re-CT ที่ Fx 3/10 = 2 Gy × 8 fx)
        แยกตามบริเวณ (อยู่ช่วง Sequential boost = แผนใหม่เป็น boost ที่เหลือ) · In = วันที่บันทึก · ขั้นตอนเริ่มใหม่ทั้งหมด
      - Re-CT: CT-Sim = วันนั้น · Start RT = "กลับมาฉายวันที่" (ว่าง = ยังไม่รู้) · ย้ายห้อง: ห้อง = ห้องใหม่ · Start RT = วันที่ย้าย
      - ขึ้นใน**งานรอ (รอ Finish)** และรายการเคสเหมือนเคสใหม่ มีป้ายแดง **↻ Re-CT · Tumor change** / **↻ ย้ายห้อง · Infinity ตลอดไป** ข้าง HN
      - **ตารางวันฉายไม่เพิ่มแถว** (ยังใช้เคสเดิมของ HN นั้น) · แดชบอร์ดนับวันฉายจากเคสเดิม · **ไม่ขยับคิวแจกเคส** · แต้ม P4P นับเหมือนเคสหนึ่งเคส
      - หน้าต่างสถานะบอกล่วงหน้า "↻ ส่งงานวางแผนใหม่ให้ WM · prescription 2 Gy × 8 fx ที่เหลือ" · ผู้ป่วยหลายเทคนิค = งานละเคสให้ MP ของแต่ละเคส
      - **เลือกผู้รับได้** (ช่อง "ส่งงานวางแผนใหม่ให้"): ค่าเริ่มต้น "ตามเดิม" = MP ของเคสเดิม (บันทึกซ้ำ = คนที่รับงานอยู่) หรือกดเลือก MP คนอื่น
        ชิปบอก "ลา" และมีคำเตือนเมื่อคนเดิมลาวันนี้ · ต้องใช้ Code.gs รุ่น 2026-10-21.3 ขึ้นไป
      - **แก้ไขงานได้** ที่หน้าแก้ไขเคส (กด HN): เปลี่ยน MP ผู้รับ prescription Start RT ฯลฯ · เปลี่ยนผู้รับแล้วยังเป็นงานวางแผนใหม่ (ไม่นับเป็นเคสเลือกเอง ไม่กระทบคิว)
      - บันทึกวันเดิมซ้ำ = แก้เหตุผล/วันเริ่มฉาย (prescription และขั้นตอนที่ทำแล้วคงไว้) · เปลี่ยนเป็นสถานะอื่นหรือล้าง = ลบงานที่ยังไม่เริ่ม
        (งานที่ Finish แล้วคงไว้ ลบเองได้ที่หน้าแก้ไขเคส)
      - แอดมินเลือกได้ที่ ตั้งค่า → สถานะ fraction: ติ๊ก "ส่งงานวางแผนใหม่ให้ MP คนเดิม" ของแต่ละสถานะ (เริ่มต้น Re-CT) และของ "ย้ายห้อง" (เริ่มต้นเปิด)
      - เก็บในคอลัมน์ `งานวางแผนใหม่ (จาก)` (JSON: เคสเดิม วันที่ สาเหตุ) · ต้องใช้ Code.gs รุ่น 2026-10-21.2 ขึ้นไป (รุ่นเก่าไม่สร้างงาน)
    - หน้าต่างบอกล่วงหน้าว่า fraction เลื่อนไปวันไหน ครบวันไหน · หมายเหตุไม่บังคับ · กดช่องที่บันทึกแล้วเพื่อแก้หรือ "ล้างสถานะ"
    - **Re-CT ครั้งที่ n**: ช่องของสถานะแสดง "Re-CT 1", "Re-CT 2" … (นับแยกตามสถานะ เรียงตามวันที่) · **fraction แรกที่กลับมาฉาย** มี "Re-CT n" สีแดงใต้เลข fraction
      (ชี้ค้าง: กลับมาฉายหลัง Re-CT ครั้งที่ n · แผนใหม่) · fraction ต่อจากนั้นชี้ค้างบอก "หลัง Re-CT ครั้งที่ n" · แถบ Complete course ก็แสดงครั้งที่
      นับสถานะ Re-CT และสถานะแบบไม่ได้ฉายที่ตั้งให้ส่งงานวางแผนใหม่
    - **แอดมินเพิ่มสถานะเองได้** ที่ ตั้งค่า → สถานะ fraction: ชื่อ คำอธิบาย การทำงาน (ฉายแล้ว · ไม่ได้ฉาย เลื่อน fraction · ฉายตามปกติ บันทึกไว้ · Off RT)
      เหตุผลให้เลือก และติ๊ก "ต้องเลือกเหตุผล" · สถานะแบบฉายตามปกติแสดงชื่อใต้เลข fraction (เช่น Port film)
    - เก็บในคอลัมน์ `สถานะ fraction` (JSON) ของแท็บ Cases · หน้าแก้ไขเคสลบไม่ได้ · ต้องใช้ Code.gs รุ่น 2026-10-17.1 ขึ้นไป
  - แถบ Complete course / Cancel RT / Off RT: แถบวันฉายของแต่ละเคส วันที่ + เลข fraction เรียงต่อกัน รวมวันที่บันทึก Hold, Re-CT ฯลฯ
    วันฉาย Sequential boost มีขีดสีส้มใต้วันที่ และแถวเคสแสดง "+ Boost … · รวม … Gy"
    สีเขียว = ฉายแล้ว · ขีดฆ่า = ยกเลิก · บอก "ฉายแล้ว x/y วัน"
  - **Complete course** (วันที่ฉายครั้งสุดท้าย หมายเหตุไม่บังคับ) และ **Cancel RT** (วันที่หยุดฉาย + **สาเหตุ บังคับ**) บันทึกจาก Off RT ในหน้าต่างสถานะ fraction ยืนยันด้วยรหัส PIN
    ผู้ป่วยที่มีหลายเทคนิค (HN เดียวกัน) บันทึกให้ทุกเคสพร้อมกัน
    บันทึกคนกดและเวลา · กดสถานะที่บันทึกแล้วเพื่อแก้ หรือ "ล้างการบันทึก" กลับเป็นกำลังฉาย · หน้าแก้ไขเคสลบสถานะนี้ไม่ได้
  - เก็บในคอลัมน์ สถานะการฉาย, วันที่จบการฉาย, สถานะการฉาย เมื่อ/โดย, สาเหตุ / หมายเหตุการฉาย ของแท็บ Cases

- **รายการเคส: การ์ด หรือ บรรทัดเดียว** (หน้างานและงานรอ ปุ่มเหนือรายการ): การ์ด = แบบเดิม เคสละหลายบรรทัดพร้อมช่องกรอกค่า
  บรรทัดเดียว = ตาราง เคสละบรรทัด ปุ่มขั้นตอนแบบย่อ (Fin, Eva, Dose, F0, D4, MC, PC) มี ✓ และค่าเมื่อบันทึกแล้ว สีตามเกณฑ์ กดเพื่อบันทึกด้วย PIN เหมือนเดิม

  - **เคสที่มี Sequential boost**: มีแถวย่อยใต้แถวของ HN นั้น (บริเวณละแถว) มีเฉพาะช่องขั้นตอน ป้าย "↳ Boost · บริเวณ" แล้วตามด้วยปุ่มขั้นตอนของแผน boost

  - **เรียงและกรองแบบ Excel**: กดชื่อคอลัมน์เพื่อเรียง (น้อย→มาก ▲ → มาก→น้อย ▼ → ไม่เรียง) · ปุ่มกรวยข้างชื่อคอลัมน์ = เลือกค่าที่แสดง

    คอลัมน์ "ขั้นตอน" กรองตามขั้นตอนถัดไป (รอ Finish, รอ Dose check, … , ครบทุกขั้นตอน) · หลายคอลัมน์รวมกันได้

  - **เลือกวันเวลาเองได้** (ลืมกดตอนทำจริง): หน้าต่าง PIN ของปุ่มขั้นตอนและปุ่ม ✓ ใต้ค่ามีช่อง วันที่ และ เวลา ค่าเริ่มต้นคือตอนนี้
    แก้ก่อนใส่ PIN · ไม่แก้ = ใช้เวลาของเซิร์ฟเวอร์เหมือนเดิม · เวลาที่ยังไม่ถึงบันทึกไม่ได้ · Evaluate ย้อนหลังโดยยังไม่ Finish ได้เวลาเดียวกันทั้งคู่
    ต้องใช้ Code.gs รุ่น 2026-10-15.1 ขึ้นไป (รุ่นเก่าไม่มีช่องนี้ บันทึกเป็นเวลาตอนนี้)
  - Evaluate ก่อน Finish: Finish ได้เวลาเดียวกัน · กด Evaluate แล้วเคสย้ายไปแถบ "เสร็จ"
  - ตั้ง/เปลี่ยนรหัส PIN: กดชื่อผู้ใช้มุมขวาบน (ยังไม่ตั้งจะมีป้าย "ตั้ง PIN") หรือตั้งตอนกดปุ่มครั้งแรก
    เปลี่ยนรหัสต้องใส่ PIN เดิม ลืม PIN ใช้รหัสผ่าน LPCH แทนได้ · ใส่ผิด 5 ครั้งล็อก 5 นาที
  - PIN เก็บแบบแฮชใน Script properties ของ Apps Script (คนที่เปิดชีตไม่เห็น)
  - **ตั้งค่า → รหัส PIN** (แอดมิน): ติ๊กเลือกกลุ่มงานที่ต้องใส่ PIN · ค่าเริ่มต้นติ๊กทุกกลุ่ม (เหมือนเดิม)
    กลุ่ม: **ปุ่มขั้นตอน** (รวม Plan 2 / boost และ ✓ ใต้ค่า) · **หน้าแก้ไขเคส** (บันทึก/ลบ) · **กิจกรรม** (RC, Brachytherapy ฯลฯ) ·
    **สถานะ fraction** (ฉายแล้ว, Hold, Re-CT, ย้ายห้อง, เพิ่ม fraction) · **Complete course / Cancel RT** · **รายละเอียดผู้ป่วย** (NPO, BD, คิว) · **Mosaiq Time** ·

    - ไม่ติ๊ก = ไม่ต้องใส่ PIN (คนที่ยังไม่ตั้ง PIN ก็บันทึกได้) · ยังบันทึกชื่อคนทำจากบัญชีที่เข้าระบบ · Code.gs ตรวจตามที่ตั้ง
    - หน้าต่างที่มีตัวเลือก (สถานะ fraction, ปุ่มขั้นตอน, รายละเอียดผู้ป่วย ฯลฯ) ยังเปิดแต่ไม่มีช่อง PIN → กด "บันทึก"
    - หน้าต่างที่มีไว้ยืนยันอย่างเดียว (บันทึกการแก้ไขเคส, บันทึก/แก้กิจกรรม, Mosaiq Time, เพิ่ม/แก้ผู้ป่วยในตารางวันฉาย) บันทึกทันทีไม่เปิดหน้าต่าง
    - การลบเคส/ลบกิจกรรมยังเปิดหน้าต่างให้กดยืนยัน (ไม่มีช่อง PIN) · ตั้ง/เปลี่ยน PIN ของตัวเองยังต้องใส่ PIN เดิมเสมอ
    - ต้องใช้ Code.gs รุ่น 2026-10-22.1 ขึ้นไป (รุ่นเก่าต้องใส่ PIN ทุกงาน หน้าตั้งค่ามีข้อความบอก)
  - **หน้าแก้ไขเคส**: กด "บันทึก" หรือ "ลบ" ต้องใส่รหัส PIN ของตัวเองก่อน (Code.gs ตรวจรหัส) · บันทึกการแก้ไขทันทีเมื่อใส่ครบ 4 หลัก
    **แก้ขั้นตอนได้จากหน้าแก้ไขเคส** (สรุปขั้นตอนด้านล่าง): ทุกขั้นตอนมีปุ่ม "แก้" (บันทึกแล้ว) หรือ "บันทึก" (ยังไม่บันทึก) → หน้าต่าง PIN ของขั้นตอนนั้นซ้อนขึ้นมา
    บันทึกใหม่ แก้ค่า หรือล้างได้ **แม้ Plan complete แล้ว** (เปิดเคสจาก HN ในตารางวันฉาย ค้นหา หรือรายการเคส) · Plan 2… / boost มีปุ่มทีละขั้นตอน
    สรุปอัปเดตทันที กดบันทึกการแก้ไขเคสทีหลังไม่ทับขั้นตอนที่เพิ่งแก้ · ใช้สิทธิ์แก้ไขเคส (คนที่เปิดหน้าแก้ไขเคสได้)
    ลบต้องกดปุ่ม "ลบเคส" สีแดงอีกครั้ง · PIN ผิดหรือกดยกเลิก กลับไปหน้าแก้ไขพร้อมสิ่งที่แก้ไว้ · ต้องใช้ Code.gs รุ่น 2026-10-12.2 ขึ้นไป
    (รุ่นเก่าบันทึกและลบแบบเดิมโดยไม่ถาม PIN)
  - **บันทึกกิจกรรมทุกอย่างใส่รหัส PIN** (RC, Daily QA, Brachytherapy, Hyperthermia, งานวิชาการ, งานบริหาร ฯลฯ ทั้งบันทึกใหม่ แก้ และลบ)
    บันทึกใหม่/แก้: ใส่ PIN ครบ 4 หลักแล้วบันทึกเลย · Brachytherapy หลายคน (+ RC) ใส่ PIN ครั้งเดียวทั้งชุด
    ลบต้องกดปุ่ม "ลบรายการ" สีแดงอีกครั้ง · ต้องใช้ Code.gs รุ่น 2026-10-12.7 ขึ้นไป (รุ่นเก่าไม่ถาม PIN)
  - เลือกปุ่ม Dose check / F0 / Delta4 / SRS MapCheck รายเทคนิคได้ที่ ตั้งค่า → เทคนิค (Finish, Evaluate, Plan complete มีเสมอ)
    SRS MapCheck เปิดไว้ให้เทคนิค SRS/SBRT/CSI เทคนิคอื่นเปิดเองได้
  - ชีต: คอลัมน์ Finish, Evaluate, Plan complete (วันเวลา) และ "… โดย", Dose check / F0 / Delta4 / SRS MapCheck (วันเวลา, โดย, ค่า)
    คอลัมน์ Plan complete ต่อท้ายตารางให้เองตอนบันทึกครั้งแรก
    คอลัมน์ชื่อเดิม MU Check / D0 จะถูกเปลี่ยนชื่อให้เองตอนบันทึกครั้งถัดไป ข้อมูลเดิมอยู่ครบ
    ช่องเหล่านี้เปลี่ยนได้จากปุ่มเท่านั้น การแก้เคสในหน้าแก้ไขเคสไม่ทับ · ต้องใช้ Code.gs รุ่น 2026-10-11.3 ขึ้นไป (SRS MapCheck)
- **สีวัน Start RT** (ในชีตคือคอลัมน์ Sim) นับ**วันทำการ** (ข้ามเสาร์–อาทิตย์และวันหยุด) เหมือนหน้างานรอ:
  เหลือ 3 วันทำการขึ้นไป สีเขียว · 2 วันทำการ สีเหลือง · 1 วันทำการ วันนี้ หรือเลยแล้ว สีแดง · แสดง "อีก N วันทำการ"
- **จำนวนครั้งในแต่ละเทคนิค**: เลือกเทคนิคแล้วมีช่อง "จำนวนครั้ง" (− 1 +) ของแต่ละเทคนิค ใส่ได้ 1–20
  เคสที่ใส่ 2 = คนนั้นได้คิวของเทคนิคนั้นไป 2 คิว: เทคนิคแรกเดินคิวตามปกติแล้วข้ามคนนั้นอีก 1 ครั้งเมื่อคิววนมาถึง
  เทคนิคถัดไปหรือเคสเลือกเอง ข้ามคนนั้นเท่าจำนวนครั้ง · แต้ม P4P และ New MU นับตามจำนวนครั้ง · รายการเคสแสดง "×2" (แก้ได้ในหน้าแก้ไขเคส)
  เก็บในคอลัมน์ `จำนวนครั้ง` ของแท็บ Cases (ว่าง = 1) ต้องใช้ Code.gs รุ่น 2026-10-10.8 ขึ้นไป
- **ห้องฉาย**: ปุ่ม Infinity / Precise / VersaHD ต่อจาก Aim (เพิ่ม/ลบห้องได้ที่ ตั้งค่า → ตัวเลือกในฟอร์ม · ตั้งบังคับกรอกได้)
- **เรียงลำดับในหน้าตั้งค่า** (แอดมิน แล้วกด "บันทึกการตั้งค่า"):
  - **เทคนิคและน้ำหนัก P4P**: ปุ่ม **↑** เลื่อนขึ้นทีละช่อง หรือ**ลากที่ ⠿** (ข้างปุ่ม ×) ไปวางเหนือ/ใต้การ์ดอื่น · ปุ่มเทคนิคในฟอร์มแจกเคสและรายการต่าง ๆ เรียงตามนี้
  - **ตัวเลือกในฟอร์ม** (Type, Aim, Technique, ความถี่, บริเวณที่ฉาย, ห้องฉาย, รายละเอียดผู้ป่วย) และตัวเลือกของหัวข้อเพิ่มเติม / เหตุผลของสถานะ fraction:
    **ใช้เมาส์ลากชิป**ไปวางซ้ายหรือขวาของชิปอื่น (มีเส้นสีบอกตำแหน่ง) · ลากได้เฉพาะในรายการเดียวกัน
  - หัวข้อเพิ่มเติมและสถานะ fraction ลากที่ ⠿ ได้เหมือนกัน (ยังมีปุ่ม ↑ เหมือนเดิม) · ไม่ต้องวาง Code.gs ใหม่
- **ฉายหลายบริเวณ**: กด **+ เพิ่มบริเวณที่ฉาย** ใต้ช่อง Dose/fx แต่ละบริเวณมีบริเวณที่ฉาย Dose/fx, Fx และความถี่ของตัวเอง กด × เพื่อลบ
  บริเวณที่ 2 ขึ้นไปเลือก "เริ่มฉายเทียบกับบริเวณที่ 1" ได้: **Concurrent** (พร้อมกัน) · **After** (หลังบริเวณที่ 1 ฉายครบ)
  · **After Fx ___** (หลัง Fx ที่กำหนดของบริเวณที่ 1 ต้องน้อยกว่าจำนวน Fx ของบริเวณที่ 1) แสดงในรายการเป็น "+ Pelvis (After Fx 15) · …"
  · **Sequential boost** (boost ต่อจากบริเวณที่ 1 ฉายครบ ถ้ามี boost หลายบริเวณ boost ถัดไปต่อจาก boost ก่อนหน้า)
  - เลือกแล้วใช้บริเวณที่ฉายและความถี่ของบริเวณที่ 1 ให้ก่อน (แก้ได้) ต้องกรอก Dose/fx, Fx, Prescription ของ boost อย่างน้อย 2 ใน 3 ช่อง
  - ใต้ช่องแสดงสรุป เช่น "เริ่มต่อจากบริเวณที่ 1 ฉายครบ · Fx 26–30 · Prescription รวม 60 Gy (50 + 10)"
  - รายการเคสแสดง "+ Chest (Sequential boost) · 2 Gy × 5 fx (10 Gy) · รวม 60 Gy/30 fx" · แถบ Complete ขีดสีส้มใต้วันฉาย boost
    และวันครบแสงนับถึงวันสุดท้ายของ boost · ใช้ Code.gs รุ่นเดิมได้ (เก็บในคอลัมน์ `บริเวณเพิ่มเติม`)
  - **ห้องฉายของบริเวณ** (ย้ายไปฉายอีกห้อง): ค่าเริ่มต้น = ห้องของบริเวณที่ 1 และเปลี่ยนตามเมื่อแก้ห้องของบริเวณที่ 1
    เลือกห้องอื่นได้ ช่องจะบอก "ย้ายจาก …" · เก็บเฉพาะเมื่อต่างจากห้องของบริเวณที่ 1 · รายการเคสแสดง "+ Pelvis (Sequential boost) · … · ห้อง Precise"
    แถบห้องฉาย: วันที่ฉายห้องอื่นมีจุดสีส้มมุมซ้ายบน (ชี้ค้างเห็นชื่อห้อง) · เลือกห้องแล้ว ผู้ป่วยที่ย้ายมาแสดงในห้องนั้น
    วันที่ยังฉายอีกห้องเป็นสีจางและไม่นับในจำนวนใต้วันที่ · แดชบอร์ด (ปฏิทินห้องฉาย) นับแต่ละวันในห้องที่ฉายจริง · ใช้ Code.gs รุ่นเดิมได้
  บริเวณแรกเก็บในคอลัมน์เดิม บริเวณที่ 2 เป็นต้นไปเก็บในคอลัมน์ `บริเวณเพิ่มเติม` (JSON) รายการเคสแสดงเป็น "+ Pelvis · 8 Gy × 1 fx"
  ห้องฉายและบริเวณเพิ่มเติมต้องใช้ Code.gs รุ่น 2026-10-10.7 ขึ้นไป
- **หัวข้อเพิ่มเติมในฟอร์มแจกเคส** (แอดมิน): ตั้งค่า → หัวข้อเพิ่มเติม → + เพิ่มหัวข้อ ตั้งชื่อ (เช่น Bolus, 4D-CT, Protocol)
  เลือกชนิด ข้อความ / ตัวเลข / วันที่ / ปุ่มเลือก 1 อย่าง / ปุ่มเลือกได้หลายอย่าง (ใส่ตัวเลือกเอง) และติ๊กบังคับกรอกได้
  หัวข้อแสดงต่อจากช่องวันที่ในฟอร์มแจกเคส ในหน้าแก้ไขเคส และในรายการเคส ค้นหาเคสด้วยค่าที่กรอกได้
  แต่ละหัวข้อเป็นคอลัมน์ของตัวเองในแท็บ `Cases` (ชื่อคอลัมน์ตั้งตามชื่อหัวข้อตอนสร้าง เปลี่ยนชื่อหัวข้อภายหลังยังใช้คอลัมน์เดิม)
  ลบหัวข้อแล้วข้อมูลเดิมยังอยู่ในชีต · ต้องใช้ Code.gs รุ่น 2026-10-10.6 ขึ้นไป
- **เข้าสู่ระบบด้วยบัญชี LPCH RO Workspace**: กดจากหน้า LPCH แล้วเข้าได้เลย มีปุ่ม Home กลับ LPCH
  **สิทธิ์ดู/บันทึกรายแถบตามตำแหน่ง** (ตั้งค่า → แถบเมนู · ค่าเริ่มต้น MP บันทึกได้ ตำแหน่งอื่นดูได้อย่างเดียว)
- **แก้การตั้งค่าได้เฉพาะแอดมิน**: คนอื่นเปิดหน้าตั้งค่าได้แต่ดูอย่างเดียว และแก้แต้มต่อในหน้าสรุป P4P ไม่ได้
- **นำเข้าข้อมูลจากไฟล์เดิม**: อ่านแท็บ 3D, 3D Bt, VM bt, VM etc, VM Chest, VM H&N, VM Brain, SRS CSI, Brachy, Hyper, RC, วิชาการ
  และแต้มต่อในแท็บ P4P โดยไม่แก้ไขแท็บเดิม (แท็บ Brachy และ Hyper นำเข้าเป็นกิจกรรมนับครั้ง)

## การคิดแต้ม (ตรงกับสูตรในแท็บ P4P)

```
แต้มต่อหน่วย  = เวลา (นาที) × น้ำหนักค่างาน × 0.143
คะแนนรวม P4P = −แต้มประกัน (1,200) + แต้มต่อ (ตั้งต้นตามตำแหน่ง) + Σ(จำนวน × แต้มต่อหน่วย) + งานวิชาการ/บริหาร (เวลา × k × 0.143)
```

ตัวอย่าง หัวหน้า: −1,200 + 360 + แต้มที่ทำได้ · ถึง 0 คือครบแต้มประกัน (ตรงกับ "ส่วนต่างแต้ม" ในแท็บ P4P และ "คะแนนรวม P4P" ในแท็บ Month)

- เคสนับให้ **MP** ตาม **วัน In** และเคสในหมวดวางแผน (3D, VMAT, SRS) ได้ **New MU** เพิ่มอีก 1 ครั้ง
- RC นับเป็น Quality Checklist ให้คนที่ RC ตามวันที่บันทึก
- แต้มต่อ = แต้มตั้งต้นของตำแหน่งในเดือนนั้น (หัวหน้า 360) แก้เป็นค่าอื่นรายคนรายเดือนได้ในหน้าสรุป P4P ลบค่าออกเพื่อกลับไปใช้ค่าตามตำแหน่ง
- เวลาและน้ำหนักของทุกหมวดแก้ได้ในหน้า **ตั้งค่า**

## กติกาคิว

1. เคสอัตโนมัติไปที่คนถัดจากคนที่ได้เคสอัตโนมัติล่าสุดของเทคนิคนั้น ตามลำดับในหน้าตั้งค่า
2. ถ้าคนนั้นลาในวัน In ของเคส หรือปิด "ปฏิบัติงาน" ไว้ ระบบข้ามไปคนถัดไป และ**เสียคิวนั้นไปเลย** จนกว่าจะกลับมาทำงาน
   เมื่อกลับมาก็รับเคสตามลำดับปกติ ไม่มีเคสชดเชย
3. เคสที่เลือกเองไม่ขยับคิว แต่บันทึกว่าคนนั้นได้เคสไปแล้ว เมื่อคิวอัตโนมัติวนมาถึงคนนั้นจะถูกข้าม 1 ครั้งต่อเคสที่เลือกเอง
   ถ้าวันที่คิววนมาถึงเขาลาอยู่ จะยังไม่หัก และรอหักรอบถัดไป หน้าตั้งค่าแสดงจำนวนที่รอหักของแต่ละเทคนิค
4. แก้ MP ของเคสที่แจกแล้ว นับเป็นเคสเลือกเอง: คิวคืนให้คนเดิม และคนใหม่ถูกข้าม 1 ครั้ง
5. เทคนิคที่ตั้งรอบคิวเป็น **รายวัน** ในหน้าตั้งค่า เคสวันเดียวกันไปที่คนเดิม วันใหม่จึงวนไปคนถัดไป (ค่าเริ่มต้นทุกเทคนิคเป็นทุกเคส)
6. ตั้งตำแหน่งคิวของแต่ละเทคนิคเองได้ในหน้าตั้งค่า (เหมือนเว้นแถวหรือสลับชื่อในไฟล์เดิม)
7. เลือกหลายเทคนิคในครั้งเดียว เทคนิคแรกเดินคิวตามปกติ เทคนิคถัดไปให้คนเดียวกัน (`follow`) คิวไม่ขยับและหักคิวคนนั้น 1 ครั้งเมื่อวนมาถึง เหมือนข้อ 3
8. บน Google Sheet ระบบเลือกคนรับเคสฝั่งเซิร์ฟเวอร์ภายใต้ล็อก ถ้าสองคนกดแจกเคสพร้อมกันก็จะไม่ได้คนเดียวกัน
   เคสหลายเทคนิคบันทึกพร้อมกันทั้งชุด ถ้าเทคนิคใดแจกไม่ได้ (เช่น ทุกคนลา) จะไม่บันทึกเคสใดในชุดนั้นเลย

ทดสอบโดยนำเข้าข้อมูลเดือนตุลาคม 2569 จากไฟล์เดิมแล้ว คะแนนรวมของทุกคนตรงกับแท็บ P4P ถึงทศนิยมตำแหน่งที่ 3

## ติดตั้งกับ Google Sheet

1. เปิดไฟล์ `P4P_Physics` ใน Google Sheets (หรือสำเนาของไฟล์)
2. เมนู **ส่วนขยาย → Apps Script**
3. ในไฟล์ `Code.gs` ให้ลบโค้ดเดิมแล้ววางเนื้อหาจาก [`Code.gs`](Code.gs)
4. หน้าเว็บ (`index.html`) **โหลดจาก GitHub อัตโนมัติ** (`PAGE_URL` ใน `Code.gs` เก็บไว้ 10 นาที) ไม่ต้องวาง
   ถ้าต้องการสำรองไว้ในโปรเจกต์ กด **＋ → HTML** ตั้งชื่อ `index` แล้ววาง [`index.html`](index.html) ระบบใช้ไฟล์นี้เมื่อโหลดจาก GitHub ไม่ได้
5. กดบันทึก แล้วกลับไปที่ชีตและรีเฟรชหน้า จะมีเมนู **ระบบกระจายงาน** เพิ่มขึ้น
6. เลือก **ระบบกระจายงาน → นำเข้าข้อมูลจากแท็บเดิม** (ครั้งแรก Google จะขอสิทธิ์ ให้กดอนุญาต)
   ระบบจะสร้างแท็บ `Cases`, `Logs`, `Leaves`, `Config` และตั้งคิวถัดไปให้ตรงกับแถวว่างในแท็บเดิม รันซ้ำได้โดยไม่เพิ่มรายการซ้ำ
7. ใช้งานได้สองแบบ
   - **ในชีต** (เจ้าของไฟล์และแอดมิน): ระบบกระจายงาน → เปิดระบบ
   - **เป็นเว็บ (ใช้บนมือถือได้)**: ใน Apps Script กด **การทำให้ใช้งานได้ → การทำให้ใช้งานได้รายการใหม่ → เว็บแอป**
     - ดำเนินการในฐานะ: **ฉัน (Me)** · ผู้ที่มีสิทธิ์เข้าถึง: **ทุกคน (Anyone)**
     - ทุกคนเข้าสู่ระบบด้วยบัญชี LPCH RO Workspace ไม่ต้องแชร์ชีตให้ทีม (สคริปต์อ่านเขียนชีตในนามเจ้าของ)
8. เลือกฟังก์ชัน **`checkSetup`** แล้วกด **เรียกใช้** (ตรวจหน้าเว็บจาก GitHub, LPCH และชีตในครั้งเดียว) (อนุญาต "เชื่อมต่อกับบริการภายนอก") บันทึกการทำงานต้องขึ้น
   `✓ เชื่อมต่อ LPCH RO Workspace ได้ และรองรับการใช้บัญชีร่วมกันแล้ว`
9. ใน LPCH RO Workspace (บัญชีผู้ดูแลระบบ) เพิ่มปุ่มหรือการ์ดแอปที่ลิงก์ไป URL `/exec` ของระบบนี้ และติ๊ก **เข้าสู่ระบบอัตโนมัติ**
   กดแล้วจะเข้าระบบนี้ด้วยบัญชี LPCH ทันที

### ใช้โปรเจกต์ Apps Script แยก (ไม่ได้เปิดจากชีต)

ถ้าสร้างโปรเจกต์จาก script.google.com โดยตรง สคริปต์ไม่ได้ผูกกับชีตใด ระบบจะเลือกชีตเก็บข้อมูลตามลำดับนี้

1. ชีตใน Script property **`SHEET_ID`** (การตั้งค่าโปรเจกต์ → คุณสมบัติของสคริปต์) ใส่ได้ทั้ง ID หรือลิงก์ของชีต
   เช่น ลิงก์ของไฟล์ `P4P_Physics` แล้วรันฟังก์ชัน **`importLegacy`** จากหน้าแก้ไขสคริปต์เพื่อนำเข้าข้อมูลเดิม (ผลอยู่ในบันทึกการทำงาน)
2. ถ้ายังไม่ได้ตั้ง ระบบสร้างชีตใหม่ชื่อ **Treatment Planning Management (ข้อมูล)** (ชีตเดิมที่มีอยู่แล้วใช้ต่อได้ ไม่ต้องเปลี่ยนชื่อ) ใน Google Drive ของบัญชีที่ Deploy ให้ครั้งแรก
   แล้วจำไว้ใน `SHEET_ID` เอง ดูลิงก์ชีตได้จาก `checkSetup` หรือ ตั้งค่า → เปิด Google Sheet

ใช้ `SHEET_ID` ไม่ได้ (ลิงก์ผิดหรือบัญชีที่ Deploy เปิดชีตนั้นไม่ได้) หน้าเว็บจะแจ้งสาเหตุ ระบบจะไม่สร้างชีตใหม่แทน

### เข้าสู่ระบบด้วยบัญชี LPCH RO Workspace

- **กดจาก LPCH**: ลิงก์แนบบัตรผ่าน (`?sso=…`) ใช้ได้ครั้งเดียว อายุ 2 นาที เข้าสู่ระบบให้ทันที
- **เปิด URL ของระบบนี้ตรง ๆ**: หน้าแรกเป็นช่องชื่อผู้ใช้หรืออีเมล + รหัสผ่านของ LPCH (ตรวจที่ LPCH ระบบนี้ไม่เก็บรหัสผ่าน)
  พร้อมปุ่มไปที่ LPCH RO Workspace
- **เว็บใช้บัญชี LPCH เสมอ รวมเจ้าของไฟล์** บัญชี Google ใช้ได้เฉพาะ ระบบกระจายงาน → เปิดระบบ ในชีต (เจ้าของไฟล์และแอดมิน)
- มุมขวาบนมีปุ่ม **Home** กลับหน้าหลัก LPCH RO Workspace ชื่อและตำแหน่งของคนที่เข้าสู่ระบบ และปุ่ม **ออกจากระบบ**
- **สิทธิ์**
  - ตั้งรายแถบได้ที่ ตั้งค่า → แถบเมนู (ไม่เห็น / ดูได้ / บันทึกได้ ต่อตำแหน่ง) · ค่าเริ่มต้น:
  - **MP** บันทึกข้อมูลได้ทุกอย่าง: แจกเคส Finish/Evaluate RC กิจกรรม และวันลา
  - **ตำแหน่งอื่น** (RO, RTT, Nurse, Other) **ดูได้อย่างเดียว** ไม่มีฟอร์มและปุ่มบันทึก (แอดมินเปิด "บันทึกได้" รายแถบได้)
  - **แอดมิน** (แก้การตั้งค่า): MP ที่เป็นผู้ดูแลระบบของ LPCH หรือ MP ที่ใส่ชื่อผู้ใช้/อีเมลไว้ใน ตั้งค่า → แอดมิน
  - เปลี่ยนตำแหน่งที่บันทึกได้ที่ `LPCH_EDIT_ROLES` ใน `Code.gs` (ค่าเริ่มต้น `['MP']`)
- ตรวจบัญชีกับ LPCH ทุกครั้งที่ใช้ (เก็บผลไว้ 5 นาที) ระงับบัญชีหรือเปลี่ยนตำแหน่งใน LPCH มีผลที่นี่ภายใน 5 นาที
- ฝั่ง Apps Script ตรวจสิทธิ์ทุกคำสั่ง ผู้ที่ดูได้อย่างเดียวเรียก API เองก็บันทึกไม่ได้
- URL ของ LPCH อยู่ที่ `LPCH_URL` ใน `Code.gs` เปลี่ยนได้ที่ Script property `LPCH_URL` (ใส่ `-` เพื่อปิดและใช้บัญชี Google แบบเดิม)

### แอดมิน

- **เจ้าของไฟล์ Google Sheet เป็นแอดมินเสมอ** เมื่อเปิดด้วยบัญชี Google (จากเมนูในชีต) ใช้ตั้งค่าครั้งแรกและนำเข้าข้อมูล
- MP ที่เป็นผู้ดูแลระบบของ LPCH เป็นแอดมินที่นี่อัตโนมัติ เพิ่ม MP คนอื่นได้ที่ ตั้งค่า → แอดมิน (ชื่อผู้ใช้หรืออีเมล LPCH)
- ระบบตรวจสิทธิ์ทั้งบนหน้าเว็บและฝั่ง Apps Script (`saveConfig`, `importLegacy`) ผู้ที่ไม่ใช่แอดมินเรียกตรงก็บันทึกการตั้งค่าไม่ได้
- ระบบไม่ให้บันทึกรายชื่อแอดมินที่ไม่มีชื่อของตัวเอง กันล็อกตัวเองออก
- เมื่อ Deploy แบบ Execute as Me ไม่ต้องแชร์ชีตให้ใคร คนที่มีสิทธิ์แก้ไขชีตโดยตรงยังแก้แท็บต่าง ๆ ได้เอง จึงแชร์เฉพาะคนที่ไว้ใจ

### อัปเดตและตรวจรุ่น

- **วาง `Code.gs` ใหม่แล้วต้องกด จัดการการทำให้ใช้งานได้ → แก้ไข → เวอร์ชันใหม่ → ทำให้ใช้งานได้** ทุกครั้ง
  URL `/exec` ใช้โค้ดของเวอร์ชันที่ Deploy ไว้ การบันทึกอย่างเดียวยังไม่เปลี่ยนสิ่งที่ผู้ใช้เห็น
- หน้าเว็บอัปเดตเองจาก GitHub ภายใน 10 นาที เปิด `…/exec?refresh=1` เพื่อโหลดรุ่นล่าสุดทันที
- ไม่แน่ใจว่าติดตั้งครบไหม: รันฟังก์ชัน **`checkSetup`** ในหน้าแก้ไขสคริปต์ ดูผลที่บันทึกการทำงาน
- ถ้าโหลดหน้าเว็บจาก GitHub ไม่ได้และไฟล์ index ในโปรเจกต์เป็นรุ่นเก่า หน้าเว็บจะมีแถบสีเหลืองบอกสาเหตุ
- อย่ากด "การทำให้ใช้งานได้รายการใหม่" ตอนอัปเดต เพราะจะได้ URL ใหม่ ลิงก์เดิมและปุ่มใน LPCH ยังเปิดรุ่นเก่า
- **วาง Code.gs ให้ถูกโปรเจกต์**: ระบบนี้กับ LPCH RO Workspace เป็นโปรเจกต์ Apps Script คนละโปรเจกต์ (คนละชีต คนละ URL `/exec`)
  ถ้าวาง Code.gs ของระบบนี้ทับในโปรเจกต์ของ LPCH: เปิด LPCH แล้วเจอหน้าระบบนี้แทน และขึ้น
  "เชื่อมต่อ LPCH RO Workspace ไม่ได้ … ไม่มี doPost" · แก้ที่โปรเจกต์ LPCH: จัดการการทำให้ใช้งานได้ → แก้ไข → เลือกเวอร์ชันก่อนหน้า → ทำให้ใช้งานได้
  (กลับมาใช้ได้ทันที) แล้ววาง Code.gs ของ LPCH กลับในโปรเจกต์นั้น และวาง Code.gs ของระบบนี้ในโปรเจกต์ของระบบนี้
- บรรทัดล่างสุดของหน้าบอก **รุ่นหน้าเว็บ · ที่มาของหน้าเว็บ (GitHub / ไฟล์ index) · รุ่น Code.gs**
  ถ้า Code.gs เก่ากว่าที่หน้าเว็บต้องการ (`API_LEVEL`) จะมีแถบเตือนให้วาง Code.gs ใหม่
- เปลี่ยนที่มาของหน้าเว็บได้ที่ Script property `PAGE_URL` (ใส่ `-` เพื่อใช้ไฟล์ index ในโปรเจกต์เท่านั้น)
  หน้าเว็บจาก GitHub ทำงานด้วยสิทธิ์ของสคริปต์นี้ ใครที่ push เข้า branch นั้นได้จึงเปลี่ยนหน้าเว็บได้ ให้สิทธิ์ repo เฉพาะคนที่ไว้ใจ
- **ถ้าหน้าเว็บเริ่มทำงานไม่ได้** จะมีกล่องสีแดงบอกสาเหตุแทนหน้าว่าง (สคริปต์ผิดพลาดพร้อมบรรทัด หรือได้รับหน้าเว็บมาไม่ครบ)
  ถ้าโค้ดที่ Google ส่งมาอ่านไม่ได้ หน้าเว็บจะใช้ต้นฉบับรุ่นเดียวกันจาก GitHub แทน และมีแถบสีเหลืองบอกบรรทัดที่เสีย
- **สำหรับผู้แก้โค้ด**: Apps Script ตัดคอมเมนต์ในสคริปต์ก่อนส่งหน้าเว็บ และตัวตัดของมันอาจตัด `//…` ที่อยู่ในสตริงทิ้งด้วย
  (เคยทำให้หน้าเว็บเปิดไม่ได้) จึงห้ามมี `//`, `/*`, `*/` ในสตริง เทมเพลต หรือ regex ในสคริปต์ของหน้าเว็บ
  ลิงก์ให้เขียน `'https:\/\/…'` แทน `'https://…'`

## ลองใช้โดยไม่ต้องติดตั้ง

เปิด `index.html` ในเบราว์เซอร์ได้เลย ระบบจะเข้าโหมดตัวอย่างพร้อมเคสสมมติ (HN ขึ้นต้นด้วย 999)
ข้อมูลในโหมดนี้เก็บไว้ในเบราว์เซอร์เครื่องนั้นเท่านั้น หน้าตั้งค่ามีปุ่มสลับมุมมอง "MP · แอดมิน / MP / ตำแหน่งอื่น" ให้ลองดูหน้าจอของแต่ละสิทธิ์

| `CTSim` | id, เครื่อง CT, วันที่, HN, Name, Organ, Mask, bitelock, CM, Coil, Y, Syring Injector, Normal Saline, Syring 50cc, แพทย์, สถานะ, HDR, C-RAD, Note, เคสวิจัย, ช่องแบบฟอร์มแจกเคส, ส่งแถบงาน, แจกเคสแล้ว (id ของเคส หรือ skip), แจกเคสโดย/เมื่อ, บันทึกโดย |
| `Config` | ทีมและประวัติตำแหน่ง, ตำแหน่งและแต้ม, แพทย์, คนถัดไปที่ตั้งเอง, เวลาและน้ำหนักของแต่ละหมวด, ตัวเลือกในฟอร์ม, หัวข้อเพิ่มเติม, ช่องบังคับกรอก, ค่าเริ่มต้นในฟอร์ม, อีเมลแอดมิน, แต้มต่อรายเดือน (JSON) |

ข้อมูลทั้งหมดเป็นข้อความล้วน เพิ่มคอลัมน์ของตัวเองต่อท้ายได้ ระบบจะไม่เขียนทับ
