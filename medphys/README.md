# ระบบกระจายงานฟิสิกส์การแพทย์

กลุ่มงานรังสีรักษา โรงพยาบาลมะเร็งลำปาง

เว็บแอปหน้าเดียวสำหรับแจกเคสวางแผนการรักษาให้นักฟิสิกส์การแพทย์ตามคิวหมุนเวียน ติดตามงานค้าง บันทึก RC และสรุปแต้ม P4P รายเดือน
ทำตามโครงสร้างของไฟล์ `P4P_Physics` เดิม ข้อมูลเก็บใน Google Sheet ของทีมเอง

## ทำอะไรได้บ้าง

- **แจกเคสใหม่**: กรอก HN รายละเอียดผู้ป่วย แล้วเลือกเทคนิค เลือกได้หลายเทคนิคในครั้งเดียว
  ระบบสร้างเคสแยกให้แต่ละเทคนิค (ใช้ข้อมูลผู้ป่วยชุดเดียวกัน) และ**ให้นักฟิสิกส์คนเดียวกันทั้งหมด**
  - **เทคนิคแรกที่กดเลือก** แจกตามคิวของเทคนิคนั้น (ชิปที่มีกรอบสองชั้นคือเทคนิคแรก กดเลือกใหม่เพื่อเปลี่ยนได้)
  - **เทคนิคถัดไป** ให้คนเดียวกันโดยไม่สนลำดับคิวของเทคนิคนั้น และนับเป็นโควตาที่ได้ไปแล้ว คิวของเทคนิคนั้นไม่ขยับ
    แต่เมื่อคิววนมาถึงคนนั้นจะถูกข้าม 1 ครั้ง (เหมือนเคสเลือกเอง) เช่น VM H&N คิวอยู่ที่ NY และเลือก VM Chest ด้วย → NY ได้ทั้งสองเคส
    และคิว VM Chest จะข้าม NY หนึ่งรอบ
  - แต้มนับตามแต่ละเทคนิค · หน้าจอแสดงก่อนกดว่าจะไปที่ใครและหักคิวไหน เลือกวิธีแจกได้สองแบบ
  - **อัตโนมัติตามคิว**: ระบบเลือก MP ให้เอง และแสดงก่อนกด "แจกเคส" ว่าเคสจะไปที่ใคร ข้ามใครเพราะอะไร
  - **เลือกเอง**: เลือกผู้รับเคสเอง คิวไม่ขยับ แต่คนนั้นจะถูกข้าม 1 ครั้งเมื่อคิววนมาถึง (หักคิวให้เท่ากัน) ถ้าเลือกหลายเทคนิค จะหักในคิวของทุกเทคนิคนั้น
  - กด "เลิกทำ" ได้ถ้าแจกผิด ทุกเคสในชุดนั้นถูกลบ คิวกลับที่เดิม และข้อมูลกลับมาอยู่ในฟอร์ม
- **บริเวณที่ฉาย**: Head, H&N, Chest, Abdomen, Pelvis, Extremity เลือกได้หลายอย่าง และ "อื่นๆ" กรอกเองได้ (คั่นด้วยจุลภาค)
  เก็บเป็นข้อความเดียว เช่น `H&N, Chest, Spine` ค้นหาในรายการงานได้ · รายการบริเวณแก้/เพิ่มได้ในหน้าตั้งค่า
- **Diag (ICD-10)**: พิมพ์รหัส (C50) ชื่อไทย (เต้านม) หรือชื่ออังกฤษ (breast) แล้วเลือกจากรายการ
  มีรหัส ICD-10 หมวดเนื้องอก C00–C97 รหัสย่อยที่ใช้ในรังสีรักษาบ่อย (เช่น C50.x, C53.x, C34.x, C71.x, C79.3, C79.5) และ D/G/L/Q บางรหัส
  พิมพ์รหัสอื่นที่ไม่มีในรายการได้ และเพิ่มรหัสหรือชื่อที่หน่วยงานใช้เองได้ในหน้าตั้งค่า
- **ขนาดรังสี**: Dose/fx (Gy), จำนวน Fx (แสดงปริมาณรังสีรวมให้อัตโนมัติ) และความถี่ในการฉาย Daily, EOD, BID, Single fraction
  หรือ "อื่นๆ" กรอกเอง · เลือก Single fraction แล้ว Fx เป็น 1 ให้เอง · รายการความถี่แก้/เพิ่มได้ในหน้าตั้งค่า
- **คิวหมุนเวียนแยกตามเทคนิค** ตามลำดับทีม JR → WM → NY → WS เหมือนคอลัมน์ MP ที่เติมไว้ล่วงหน้าในแต่ละแท็บ
  ใครได้เคสแล้ว เคสถัดไปของเทคนิคนั้นจะวนไปคนต่อไป
- **วันลา**: กด "ลาวันนี้" ที่การ์ดของแต่ละคน หรือ "จัดการวันลา" เพื่อลงวันลาล่วงหน้าเป็นช่วงวัน
  คนที่ลาในวัน In ของเคสจะไม่ได้รับเคส ระบบข้ามไปคนถัดไปและไม่ทำให้ใครได้เคสซ้ำสองครั้งติด
- **ติดตามงานค้าง**: เรียงตามวัน Start RT พร้อมบอกว่าเหลืออีกกี่วันหรือเลยกำหนดมาแล้ว กดปุ่ม `Finish` หรือ `Evaluate` เพื่อลงวันที่เป็นวันนี้ทันที
- **RC (Quality Checklist)**: กด `+ RC` ที่เคส ระบบแนะนำคนที่ RC น้อยที่สุดเดือนนี้ (ไม่ใช่ผู้วางแผน) และบันทึก RC ที่ไม่ผูกกับเคสได้ เช่น RC Decay
- **RC และกิจกรรมเป็นการบันทึกงานที่ทำแล้ว** ไม่เกี่ยวกับคิวแจกงาน วันลาจึงไม่มีผล (เลือกใครก็ได้ ระบบไม่ข้ามและไม่เตือนเรื่องลา)
- **Brachytherapy และ Hyperthermia**: เป็นกิจกรรมนับครั้งในหน้า "RC และกิจกรรม" ไม่ได้แจกตามคิว
  - แถบ **Brachytherapy** รวม Brachy 3D และ Brachy เสียบเข็ม · แถบ **Hyperthermia** รวม Plan to heat และ Hyperthermia control
  - กด "+ กิจกรรมอื่น" ในแถบนั้น เลือกกิจกรรม MP วันที่ HN และชื่อผู้ป่วย แต้มนับตามจำนวนครั้ง × เวลา × น้ำหนัก
  - ในหน้าตั้งค่า (กิจกรรมนับครั้ง) แก้ชื่อ แถบ กลุ่มในแบบ P4P เวลา น้ำหนัก และเลือกว่าบันทึก HN หรือไม่ได้
    เพิ่มกิจกรรมใหม่เข้าแถบเดิมได้ หรือลบชื่อแถบเพื่อให้มีแถบของตัวเอง
  - เคส Brachy/Hyperthermia ที่บันทึกไว้แบบเดิม (แท็บ Cases) ย้ายไปเป็นกิจกรรมในแท็บ Logs ให้เองครั้งแรกที่เปิดระบบ แต้มเท่าเดิม
- **กิจกรรมอื่น**: Daily QA, งานวิชาการ, งานบริหาร (เวลา × k)
- **ตำแหน่ง**: เลือกตำแหน่งให้แต่ละคนในหน้าตั้งค่า ค่าเริ่มต้นมี "หัวหน้า" (แต้มตั้งต้น 360/เดือน) และ "นักฟิสิกส์การแพทย์" (0)
  แก้ชื่อ แต้มตั้งต้น แต้มประกัน หรือเพิ่มตำแหน่งได้ เปลี่ยนตำแหน่งของใครมีผลตั้งแต่เดือนนั้น เดือนก่อนหน้าคิดตามตำแหน่งเดิม
- **สรุป P4P**: ทุกคนเริ่มเดือนที่แต้มประกัน −1,200 (หัวหน้าเริ่มที่ −840 เพราะมีแต้มตั้งต้น 360) แล้วบวกแต้มที่ทำได้จนได้คะแนนรวม
  มีตารางเทียบทุกคน และ**ใบคะแนนรายคน**ที่แสดงยอดสะสมทีละกิจกรรมแบบแบบฟอร์ม P4P เดิม พร้อมสถิติเคสตาม Type / Aim แบบแท็บ Month
- **ดาวน์โหลด Excel** (ปุ่มในหน้าสรุป P4P): แบบจัดเก็บคะแนนภาระงาน (Activity base) ของเดือนที่เลือก แบบแท็บ P4P เดิม
  - เลือก "ทุกคน" = 1 แผ่นงานต่อคน · เลือกชื่อ = เฉพาะคนนั้น · ไฟล์ชื่อ `P4P-2569-10.xlsx` (หรือ `P4P-2569-10-JR.xlsx`)
  - คนละ 3 หน้า A4 แนวนอน: งานห้อง / 3D / IMRT · VMAT / Brachytherapy / Hyperthermia · งานวิชาการ / งานบริหาร + สรุปแต้ม
    (แต้มประกัน แต้มต่อ แต้มที่ทำได้ ส่วนต่างแต้ม) · เทคนิคหรือกิจกรรมที่เพิ่มเองอยู่ในกลุ่มของมัน กลุ่มที่ไม่พอหน้าขึ้นหน้าใหม่
  - จำนวนรายวัน 1–31 ตามวัน In ของเคส (เทคนิค + New MU ตามจำนวนครั้ง) และวันที่ของบันทึก RC / กิจกรรม · ไม่มี = "-"
    เสาร์–อาทิตย์และวันหยุดเป็นสีเขียว · งานวิชาการ/บริหาร บันทึกละแถว (เวลา × k × แต้มมาตรฐาน)
  - รวม ทำได้ แต้ม/หน่วย และสรุปแต้มเป็นสูตร แก้จำนวนในไฟล์แล้วคำนวณใหม่ · ตัวเลขตรงกับหน้าสรุป P4P
  - แถวในแบบฟอร์มที่ยังไม่ได้ใช้ (3D Brain tumor, กลุ่ม IMRT) ใส่ไว้ให้ครบ นับเป็น 0
  - หัวกระดาษใช้ชื่อ-สกุล และ "ตำแหน่งในแบบฟอร์ม" ของแต่ละคน (ตั้งค่า → ทีม · ไม่ใส่ = ใช้ชื่อตำแหน่งในระบบ)
    และ "กลุ่มที่" (ตั้งค่า → เทคนิคและน้ำหนัก P4P) · ฟอนต์ TH Sarabun PSK
  - สร้างไฟล์ในเบราว์เซอร์ด้วย ExcelJS (โหลดจาก cdnjs หรือ jsDelivr ตอนกดปุ่ม) ไม่ต้องอัปเดต Code.gs
- **ตั้งค่าได้ทุกหัวข้อ**: เพิ่ม/แก้ทีมและตำแหน่ง, เพิ่มเทคนิคใหม่ (ชื่อ, กลุ่มในแบบ P4P, ประเภท, เวลา, น้ำหนัก, รอบคิว, New MU, Technique),
  เพิ่มกิจกรรมนับครั้ง (เช่น Machine QA) ซึ่งจะเป็นตัวเลือกในหน้า RC และกิจกรรมและนับแต้มใน P4P,
  เพิ่ม/ลบตัวเลือก Type, Aim, Technique, ความถี่, บริเวณที่ฉาย · เทคนิคหรือกิจกรรมที่มีข้อมูลแล้วลบไม่ได้ (ปิด "แสดงในฟอร์ม" แทน)
- **แพทย์ (Doc)**: เพิ่ม/ลบ/เรียงลำดับได้แบบเดียวกับทีมนักฟิสิกส์ แต่ละคนมีรหัสและชื่อ-สกุล (ไม่บังคับ)
  ปุ่มในฟอร์มแสดงรหัส ชี้ที่รหัสเพื่อดูชื่อ และค้นหาเคสด้วยชื่อแพทย์ได้
- **ช่องบังคับกรอก**: เลือกได้ว่าช่องไหนในฟอร์มแจกเคสต้องกรอก (Name, Doc, Diag, บริเวณที่ฉาย, Type, Aim, Technique, Dose/fx, Fx,
  ความถี่, CT-Sim, Start RT, Note) ช่องที่บังคับมี * ในฟอร์ม และกด "แจกเคส" ไม่ได้จนกว่าจะกรอก
  HN และเทคนิคบังคับเสมอ · ช่องของงานวางแผน (Doc, Type, Aim, Technique, CT-Sim, Start RT) บังคับเฉพาะเมื่อเลือกเทคนิคที่เป็นงานวางแผน · "on call" นับว่ากรอก Start RT แล้ว
- **ค่าเริ่มต้นในฟอร์มแจกเคส** (ตั้งค่า → ค่าเริ่มต้นและช่องบังคับกรอก ตารางเดียวกับช่องบังคับ): แต่ละช่องเลือกค่าเริ่มต้นหรือ "ไม่มี" ได้
  Doc, เทคนิค, Type, Aim, ห้องฉาย, Technique, บริเวณที่ฉาย, Dose/fx, Fx, ความถี่, CT-Sim, Start RT, Note และหัวข้อเพิ่มเติม (ตั้งที่หัวข้อนั้น)
  - ฟอร์มใส่ค่าเริ่มต้นให้ตอนเปิด หลังแจกเคส และเมื่อกด "ล้างฟอร์ม" แก้หรือเอาออกในฟอร์มได้ (กดปุ่มที่เลือกอยู่ซ้ำ = เอาออก)
  - วันที่ตั้งเป็นจำนวนวันทำการนับจากวันแจก (0 = วันแจก, −1 = วันทำการก่อนหน้า) ข้ามเสาร์–อาทิตย์และวันหยุด · Start RT ตั้งเป็น on call ได้
  - เทคนิคและบริเวณที่ฉาย (เลือกได้หลายอย่าง): กดเลือกอย่างอื่นครั้งแรกจะเปลี่ยนแทนค่าเริ่มต้น ไม่แจกเป็น 2 เทคนิคโดยไม่ตั้งใจ
  - ตั้ง Dose/fx และ Fx ไว้ทั้งคู่: กรอก Prescription แล้ว Fx คำนวณใหม่ (Dose/fx คงไว้) · ความถี่ Single fraction ที่ไม่ได้ตั้ง Fx ใส่ Fx 1
  - แก้ค่าเริ่มต้นแล้ว ฟอร์มที่ยังไม่ได้กรอกเปลี่ยนตามทันที ฟอร์มที่กำลังกรอกอยู่ไม่ถูกทับ · ตัวเลือกที่ถูกลบไปแล้วไม่ใช้เป็นค่าเริ่มต้น
  - เริ่มต้นตั้งไว้ Type = New เหมือนเดิม · ไม่ต้องอัปเดต Code.gs
- **ค่าเริ่มต้นตามเทคนิค, Type หรือ ICD-10** (ตารางถัดไปในส่วนเดียวกัน): แต่ละแถวเลือกเงื่อนไข เทคนิค / Technique / Type / ICD-10
  แล้วตั้ง Dose/fx, Fx, ความถี่, ห้องฉาย, บริเวณที่ฉาย, Aim (แสดง Prescription ที่ได้ให้ดู)
  - เช่น เทคนิค VM H&N → ห้องฉาย Infinity และบริเวณ H&N · Type Emer high → Aim Palliative · Type New → Aim Curative
  - เลือกเทคนิค, Technique, Type หรือ Diag ที่ตรงในฟอร์มแล้วใส่ค่าให้ทันที เปลี่ยนแล้วเปลี่ยนตาม
    เฉพาะช่องที่ยังไม่ได้แก้เอง (แก้ Dose/fx, Fx หรือกรอก Prescription เองแล้ว Dose/fx กับ Fx ไม่เปลี่ยนอีก · เลือกห้อง บริเวณ หรือ Aim เองแล้วไม่ทับ)
  - บริเวณที่ฉายที่ระบบใส่ให้: กดเลือกบริเวณอื่นครั้งแรกจะเปลี่ยนแทน ไม่เพิ่มต่อ
  - ตรงหลายแถว: Technique ก่อน แล้วเทคนิคแรกที่เลือก แล้ว Type แล้ว ICD-10 (รหัสยาวกว่าก่อน) แล้วค่าเริ่มต้นทั่วไป
    Dose/fx กับ Fx มาคู่กันจากแถวเดียว ไม่ปนกันระหว่างแถว
  - ICD-10 ใส่รหัสหรือต้นรหัส เช่น C61 หรือ C50 (ตรงกับ C50.0–C50.9)
  - ตั้งไว้ให้แล้ว: 3D Breast และ VM Breast 16 fx · Technique SRS 1 fx (SBRT/CSI ไม่ใช่) · ICD-10 C61 (Prostate) 2.5 Gy × 28 fx = 70 Gy
  - Type → Aim ตั้งไว้ให้จากไฟล์ P4P เดิม (Aim ที่ใช้บ่อยที่สุดของแต่ละ Type): New → Curative · Emer low, Emer high → Palliative
    · Replan, Adap → On tx · CP → Curative (มี 1 เคส) · การตั้งค่าที่บันทึกไว้ก่อนแล้วได้แถวเหล่านี้เพิ่มครั้งเดียว
    · ไฟล์เดิมไม่มีห้องฉายและบริเวณที่ฉาย จึงยังไม่มีกฎของเทคนิค
    แก้หรือลบได้ ลบหมดแล้วไม่กลับมาเอง
- **แถบเมนู** (ตั้งค่า → แถบเมนู): แอดมินจัดลำดับแถบ งาน / งานรอ / แดชบอร์ด / RC และกิจกรรม / สรุป P4P / ตั้งค่า (กด ↑)
  และเลือกแถบที่แสดง ใช้กับทุกคน · "ตั้งค่า" แสดงเสมอ · คนที่เปิดแถบที่ถูกซ่อนค้างไว้จะเปิดที่แถบแรกที่แสดงแทน
  - ช่อง **"ตำแหน่งอื่น"**: แถบที่คนที่ไม่ใช่ MP (RO, RTT, พยาบาล ฯลฯ) ดูได้ (ดูอย่างเดียว) · ค่าเริ่มต้นติ๊กทุกแถบ (เหมือนเดิม)
    แถบที่ไม่ได้ติ๊ก "แสดง" ตำแหน่งอื่นก็ไม่เห็น · ไม่ติ๊กเลย = ตำแหน่งอื่นเข้าแล้วเห็นข้อความ "ยังไม่มีแถบที่ดูได้"
  - Code.gs รุ่น 2026-10-12.2 ขึ้นไปส่งให้ตำแหน่งอื่นเฉพาะข้อมูลที่แถบที่เปิดให้ดูใช้
    (เคส: งาน งานรอ แดชบอร์ด สรุป P4P · RC และกิจกรรม: งาน งานรอ RC และกิจกรรม สรุป P4P · วันลา: งาน) ไม่ได้ซ่อนแค่ปุ่มแถบ
- **โหมดกลางวัน/กลางคืน**: ปุ่มรูปพระจันทร์/พระอาทิตย์มุมขวาบน ยังไม่เคยกด = ตามการตั้งค่าของเครื่อง กดแล้วจำไว้ในเบราว์เซอร์นั้น
- **งานรอ** (เมนู "งานรอ" ต่อจาก "งาน"): รอ Finish, Evaluate, Dose check, F0, Delta4, SRS MapCheck, Plan complete (เฉพาะปุ่มที่เทคนิคนั้นมี)
  กดการ์ดเพื่อดูรายการพร้อมปุ่มบันทึก · กรองห้องฉายได้ · ตรวจ QA และ Plan complete นับเฉพาะเคสที่ยังไม่ Evaluate หรือ Start RT ไม่เกิน 7 วันที่แล้ว
  - "Start RT เร็วสุด" เหลือ 2 วันทำการ = **สีเหลือง** · เหลือ 1 วันทำการหรือถึง/เลยวันแล้ว = **สีแดง** (นับเฉพาะวันทำการ ข้ามเสาร์–อาทิตย์และวันหยุด
    เช่น วันศุกร์ เคส Start RT วันจันทร์ = เหลือ 1 วันทำการ) · เคสที่ Start RT เลยมาเกิน 7 วันไม่นับเป็นงานด่วน
  - วงกลมบนแถบ "งานรอ" บอกจำนวนเคสด่วน (เคสเดียวรอหลายขั้นนับครั้งเดียว ทุกห้อง) สีแดงเมื่อมีเคสสีแดงอย่างน้อย 1 เคส ไม่งั้นสีเหลือง
    ไม่มีงานด่วน = ไม่มีวงกลม · ชี้ที่แถบเพื่อดูว่าแดงกี่เคส เหลืองกี่เคส
- **แดชบอร์ด** (เมนู "แดชบอร์ด")
  - **ปฏิทินห้องฉาย** เริ่มสัปดาห์วันอาทิตย์: จำนวนผู้ป่วยที่กำลังฉายแต่ละห้องในแต่ละวัน
    - **มุมมอง** วัน / สัปดาห์ / เดือน / 3 เดือน / ปี (จำไว้ในเบราว์เซอร์) · ‹ › เลื่อนตามมุมมอง · "วันนี้" กลับวันนี้ · เดือนด้านบนตามไปด้วย
    - วัน: รายชื่อของวันนั้น · สัปดาห์: 7 ช่องใหญ่ · 3 เดือน และ ปี: ปฏิทินเดือนเล็ก สีเข้มตามจำนวนผู้ป่วยที่กำลังฉาย
      (3 เดือนมีตัวเลขและจุดสีของเหตุการณ์ใต้วันที่ · ปี ชี้ที่วันเพื่อดูจำนวน) · กดวันเพื่อดูรายชื่อ
    เลือกแสดงเพิ่มได้: เริ่มฉาย (Start RT), ครบแสง, CT-Sim, รับเคส (In), Finish, Evaluate · กรองห้องได้ · กดวันเพื่อดูรายชื่อ (กดชื่อเพื่อเปิดเคส)
    วันฉายคำนวณจาก Start RT, Fx และความถี่ (Daily, BID = 2 fx/วัน, EOD = วันเว้นวัน, Single fraction, Weekly)
    ข้ามเสาร์–อาทิตย์และวันหยุด · บริเวณที่ 2 ขึ้นไปนับตาม Concurrent / After / After Fx · ผู้ป่วยหลายเทคนิคนับครั้งเดียว
  - **สถิติแต่ละเทคนิค**: เคส ครั้ง แยกห้อง Curative/Palliative กำลังฉายวันนี้ รอ Finish · ช่วงเวลา เดือนที่เลือก / 3 / 12 เดือน / ทั้งหมด / **กำหนดเอง** (ตามวัน In)
    - กำหนดเอง: เลือกวัน "ตั้งแต่" และ "ถึง" จากปฏิทิน (เริ่มที่เดือนที่เลือก) · ปุ่ม "ใช้ช่วงของปฏิทินด้านบน" ใช้ช่วงที่ปฏิทินแสดงอยู่ (เช่นสัปดาห์นั้น)
    - ใช้ช่วงเดียวกันกับระยะเวลารอคอย · ใส่กลับด้านจะสลับให้ · ว่างด้านใดคือไม่จำกัดด้านนั้น
  - **ระยะเวลารอคอย**: CT-Sim → In → Finish → Evaluate → Dose check → F0 → Start RT (เฉลี่ย มัธยฐาน เร็วสุด นานสุด)
    เลือกช่วงอื่นเองได้ · นับเป็นวัน (ใช้เวลาที่กดปุ่มถ้ามี) หรือวันทำการ · กรองเทคนิคได้
- **วันหยุด** (ตั้งค่า → วันหยุด): เริ่มต้นมีวันหยุดราชการที่ตรงวันทุกปี กด "ดึงวันหยุดราชการไทย ปี …" เพื่อดึงทั้งหมด
  (รวมวันหยุดตามจันทรคติและวันหยุดชดเชย) จากปฏิทินวันหยุดของ Google ผ่าน Code.gs รุ่น 2026-10-11.4 ขึ้นไป · เพิ่ม แก้ ลบเองได้ แล้วกดบันทึกการตั้งค่า
- **ช่องวันที่ (CT-Sim, Start RT ฯลฯ)**: คลิกช่องที่ว่างแล้วขึ้นวันนี้ เดือนและปีเป็นปัจจุบัน พิมพ์แค่วันที่ (ใช้บนคอม)
  ไม่ได้แก้อะไรแล้วออกจากช่อง ช่องกลับเป็นว่าง · มือถือใช้ปฏิทินของเครื่องตามเดิม
- **CT-Sim, In, Start RT ต้องเป็นวันทำการ** (ฟอร์มแจกเคสและหน้าแก้ไขเคส): เลือกเสาร์ อาทิตย์ หรือวันหยุด (ตั้งค่า → วันหยุด)
  ขึ้นข้อความเตือน เช่น "17 ต.ค. 2569 เป็นวันเสาร์ · Start RT ต้องเป็นวันทำการ" แล้วช่องกลับเป็นค่าเดิม กด "แจกเคส" ไม่ได้ถ้ายังเป็นวันหยุด
  - เลือกจากปฏิทินตรวจทันที · พิมพ์เองตรวจตอนออกจากช่อง (ระหว่างพิมพ์ เช่น 3 → 31 ไม่เตือน)
  - เปิดฟอร์มวันเสาร์–อาทิตย์หรือวันหยุด: In และช่องที่คลิกแล้วขึ้นวันนี้ ใช้วันทำการถัดไปแทน · ค่าเริ่มต้นวันที่นับจาก In
  - เคสเก่าที่มีวันเสาร์–อาทิตย์อยู่แล้ว แก้ช่องอื่นแล้วบันทึกได้ตามเดิม · วันลาและวันที่อื่นไม่เกี่ยว
- **Dose/fx · Fx · Prescription (Gy)**: กรอก 2 ช่องไหนก็ได้ อีกช่องคำนวณให้ (มีป้าย "คำนวณ" และกรอบเส้นประ)
  ช่องที่กรอกเองไว้นานที่สุดคือช่องที่ถูกคำนวณใหม่ · Prescription ที่กรอกเองเก็บตามที่กรอก (40 Gy / 15 fx = 2.667 Gy/fx แต่แสดง 40 Gy)
  Fx ที่คำนวณได้ไม่เป็นจำนวนเต็มจะเตือนก่อนบันทึก · ใช้ได้ทุกบริเวณที่ฉาย · เก็บในคอลัมน์ `Prescription (Gy)` (Code.gs รุ่น 2026-10-11.2 ขึ้นไป)
- **ปุ่มบันทึกขั้นตอน Finish · Evaluate · Dose check · F0 · Delta4 · SRS MapCheck · Plan complete** (ใต้ข้อมูลเคสวางแผนแต่ละแถว)
  - **Plan complete** อยู่ชิดขวาสุดของแถว มีทุกเทคนิค ไม่ต้องกรอกค่า (ใส่ PIN แล้วบันทึกคนกด วันเวลา) · ต้องใช้ Code.gs รุ่น 2026-10-12.1 ขึ้นไป
    Code.gs รุ่นเก่ายังไม่แสดงปุ่มนี้
  - กดแล้วใส่**รหัส PIN 4 หลักของตัวเอง** ระบบบันทึกชื่อคนกด วันและเวลา (เวลาของเซิร์ฟเวอร์) แสดงตัวเล็กใต้ปุ่ม
  - Dose check, F0, Delta4, SRS MapCheck ต้องกรอกค่าก่อนบันทึก ค่าแสดงบนปุ่ม (เช่น Dose check 1.2%)
  - **ช่องกรอกเล็กใต้ปุ่ม** Dose check / F0 / Delta4 / SRS MapCheck ที่ยังไม่บันทึก พร้อมปุ่ม **✓** ของแต่ละค่า: บันทึก**ทีละค่า**
    กด ✓ หรือ Enter ในช่อง → ใส่รหัส PIN → บันทึกค่านั้น · ค่าที่พิมพ์ในช่องอื่นยังอยู่ · ค่าที่พิมพ์ไว้ไม่หายเมื่อหน้าวาดใหม่
  - **หน่วยเริ่มต้นเป็น %**: พิมพ์แค่ตัวเลข (เช่น 1.2) บันทึกเป็น 1.2% ทั้งในช่องใต้ปุ่มและหน้าต่างที่กดจากปุ่ม · ท้ายช่องมี % ให้เห็น
    พิมพ์หน่วยหรือข้อความเอง (เช่น 98.7% หรือ 0.3 cGy) บันทึกตามที่พิมพ์ และ % ท้ายช่องจะหายไป
  - **สีของค่า** (ตั้งค่า → สีของค่า QA แอดมินตั้ง): ปุ่มที่บันทึกแล้วเป็นสีเขียว/เหลือง/แดงตามเกณฑ์ ช่องกรอกเปลี่ยนสีระหว่างพิมพ์
    - "ยิ่งมากยิ่งดี": ≥ ค่าเขียว = เขียว · ≥ ค่าเหลือง = เหลือง · ต่ำกว่านั้นแดง (ค่าเริ่มต้น Delta4 และ SRS MapCheck: ≥ 95 เขียว, 90–95 เหลือง, < 90 แดง)
    - "ยิ่งใกล้ 0 ยิ่งดี": ใช้ค่าสัมบูรณ์ เช่น Dose check ±3 เขียว, ±3–5 เหลือง, เกิน ±5 แดง (Dose check และ F0 เริ่มต้นไม่ใช้สี)
    - ใช้ตัวเลขในค่า (98.5% = 98.5) · ค่าที่ไม่มีตัวเลขไม่มีสี
  - **หมายเหตุของค่า** (ไม่บังคับ): ช่อง "หมายเหตุ" ในหน้าต่าง PIN ตอนบันทึกค่า ค่าที่เป็นสีแดงจะเปิดที่ช่องหมายเหตุก่อน
    หมายเหตุแสดงตัวเล็กใต้ปุ่ม (ชี้เพื่อดูเต็ม) และในหน้าแก้ไขเคส · แก้ได้โดยกดปุ่มที่บันทึกแล้ว · ล้างค่าแล้วหมายเหตุหายด้วย
    เก็บในคอลัมน์ "Dose check หมายเหตุ", "F0 หมายเหตุ", "Delta4 หมายเหตุ", "SRS MapCheck หมายเหตุ" · ต้องใช้ Code.gs รุ่น 2026-10-12.4 ขึ้นไป
  - ใส่ PIN ครบ 4 หลักแล้วบันทึกทันที · กด "เลิกทำ" ได้ทันทีหลังบันทึก · กดปุ่มที่บันทึกแล้วเพื่อบันทึกใหม่หรือ "ล้างการบันทึก" (ใช้ PIN)
  - Evaluate ก่อน Finish: Finish ได้เวลาเดียวกัน · กด Evaluate แล้วเคสย้ายไปแถบ "เสร็จ"

  - เลือกปุ่ม Dose check / F0 / Delta4 / SRS MapCheck รายเทคนิคได้ที่ ตั้งค่า → เทคนิค (Finish, Evaluate, Plan complete มีเสมอ)
    SRS MapCheck เปิดไว้ให้เทคนิค SRS/SBRT/CSI เทคนิคอื่นเปิดเองได้
  - ชีต: คอลัมน์ Finish, Evaluate, Plan complete (วันเวลา) และ "… โดย", Dose check / F0 / Delta4 / SRS MapCheck (วันเวลา, โดย, ค่า)
    คอลัมน์ Plan complete ต่อท้ายตารางให้เองตอนบันทึกครั้งแรก
    คอลัมน์ชื่อเดิม MU Check / D0 จะถูกเปลี่ยนชื่อให้เองตอนบันทึกครั้งถัดไป ข้อมูลเดิมอยู่ครบ
    ช่องเหล่านี้เปลี่ยนได้จากปุ่มเท่านั้น การแก้เคสในหน้าแก้ไขเคสไม่ทับ · ต้องใช้ Code.gs รุ่น 2026-10-11.3 ขึ้นไป (SRS MapCheck)

- **ห้องฉาย**: ปุ่ม Infinity / Precise / VersaHD ต่อจาก Aim (เพิ่ม/ลบห้องได้ที่ ตั้งค่า → ตัวเลือกในฟอร์ม · ตั้งบังคับกรอกได้)
- **ฉายหลายบริเวณ**: กด **+ เพิ่มบริเวณที่ฉาย** ใต้ช่อง Dose/fx แต่ละบริเวณมีบริเวณที่ฉาย Dose/fx, Fx และความถี่ของตัวเอง กด × เพื่อลบ
  บริเวณที่ 2 ขึ้นไปเลือก "เริ่มฉายเทียบกับบริเวณที่ 1" ได้: **Concurrent** (พร้อมกัน) · **After** (หลังบริเวณที่ 1 ฉายครบ)
  · **After Fx ___** (หลัง Fx ที่กำหนดของบริเวณที่ 1 ต้องน้อยกว่าจำนวน Fx ของบริเวณที่ 1) แสดงในรายการเป็น "+ Pelvis (After Fx 15) · …"
  บริเวณแรกเก็บในคอลัมน์เดิม บริเวณที่ 2 เป็นต้นไปเก็บในคอลัมน์ `บริเวณเพิ่มเติม` (JSON) รายการเคสแสดงเป็น "+ Pelvis · 8 Gy × 1 fx"
  ห้องฉายและบริเวณเพิ่มเติมต้องใช้ Code.gs รุ่น 2026-10-10.7 ขึ้นไป
- **หัวข้อเพิ่มเติมในฟอร์มแจกเคส** (แอดมิน): ตั้งค่า → หัวข้อเพิ่มเติม → + เพิ่มหัวข้อ ตั้งชื่อ (เช่น Bolus, 4D-CT, Protocol)
  เลือกชนิด ข้อความ / ตัวเลข / วันที่ / ปุ่มเลือก 1 อย่าง / ปุ่มเลือกได้หลายอย่าง (ใส่ตัวเลือกเอง) และติ๊กบังคับกรอกได้
  หัวข้อแสดงต่อจากช่องวันที่ในฟอร์มแจกเคส ในหน้าแก้ไขเคส และในรายการเคส ค้นหาเคสด้วยค่าที่กรอกได้
  แต่ละหัวข้อเป็นคอลัมน์ของตัวเองในแท็บ `Cases` (ชื่อคอลัมน์ตั้งตามชื่อหัวข้อตอนสร้าง เปลี่ยนชื่อหัวข้อภายหลังยังใช้คอลัมน์เดิม)
  ลบหัวข้อแล้วข้อมูลเดิมยังอยู่ในชีต · ต้องใช้ Code.gs รุ่น 2026-10-10.6 ขึ้นไป
- **เข้าสู่ระบบด้วยบัญชี LPCH RO Workspace**: กดจากหน้า LPCH แล้วเข้าได้เลย มีปุ่ม Home กลับ LPCH
  **MP บันทึกข้อมูลได้ ตำแหน่งอื่นดูได้อย่างเดียว** (ดูหัวข้อ "เข้าสู่ระบบด้วยบัญชี LPCH RO Workspace")
- **แก้การตั้งค่าได้เฉพาะแอดมิน**: คนอื่นเปิดหน้าตั้งค่าได้แต่ดูอย่างเดียว และแก้แต้มต่อในหน้าสรุป P4P ไม่ได้
- **นำเข้าข้อมูลจากไฟล์เดิม**: อ่านแท็บ 3D, 3D Bt, VM bt, VM etc, VM Chest, VM H&N, VM Brain, SRS CSI, Brachy, Hyper, RC, วิชาการ
  และแต้มต่อในแท็บ P4P โดยไม่แก้ไขแท็บเดิม (แท็บ Brachy และ Hyper นำเข้าเป็นกิจกรรมนับครั้ง)

## การคิดแต้ม (ตรงกับสูตรในแท็บ P4P)

```
แต้มต่อหน่วย  = เวลา (นาที) × น้ำหนักค่างาน × 0.143
คะแนนรวม P4P = −แต้มประกัน (1,200) + แต้มต่อ (ตั้งต้นตามตำแหน่ง) + Σ(จำนวน × แต้มต่อหน่วย) + งานวิชาการ/บริหาร (เวลา × k × 0.143)
```

ตัวอย่าง หัวหน้า: −1,200 + 360 + แต้มที่ทำได้ · ถึง 0 คือครบแต้มประกัน (ตรงกับ "ส่วนต่างแต้ม" ในแท็บ P4P และ "คะแนนรวม P4P" ในแท็บ Month)

- เคสนับให้ **MP** ตาม **วัน In** และเคสในหมวดวางแผน (3D, VMAT, SRS) ได้ **New MU** เพิ่มอีก 1 ครั้ง
- RC นับเป็น Quality Checklist ให้คนที่ RC ตามวันที่บันทึก
- แต้มต่อ = แต้มตั้งต้นของตำแหน่งในเดือนนั้น (หัวหน้า 360) แก้เป็นค่าอื่นรายคนรายเดือนได้ในหน้าสรุป P4P ลบค่าออกเพื่อกลับไปใช้ค่าตามตำแหน่ง
- เวลาและน้ำหนักของทุกหมวดแก้ได้ในหน้า **ตั้งค่า**

## กติกาคิว

1. เคสอัตโนมัติไปที่คนถัดจากคนที่ได้เคสอัตโนมัติล่าสุดของเทคนิคนั้น ตามลำดับในหน้าตั้งค่า
2. ถ้าคนนั้นลาในวัน In ของเคส หรือปิด "ปฏิบัติงาน" ไว้ ระบบข้ามไปคนถัดไป และ**เสียคิวนั้นไปเลย** จนกว่าจะกลับมาทำงาน
   เมื่อกลับมาก็รับเคสตามลำดับปกติ ไม่มีเคสชดเชย
3. เคสที่เลือกเองไม่ขยับคิว แต่บันทึกว่าคนนั้นได้เคสไปแล้ว เมื่อคิวอัตโนมัติวนมาถึงคนนั้นจะถูกข้าม 1 ครั้งต่อเคสที่เลือกเอง
   ถ้าวันที่คิววนมาถึงเขาลาอยู่ จะยังไม่หัก และรอหักรอบถัดไป หน้าตั้งค่าแสดงจำนวนที่รอหักของแต่ละเทคนิค
4. แก้ MP ของเคสที่แจกแล้ว นับเป็นเคสเลือกเอง: คิวคืนให้คนเดิม และคนใหม่ถูกข้าม 1 ครั้ง
5. เทคนิคที่ตั้งรอบคิวเป็น **รายวัน** ในหน้าตั้งค่า เคสวันเดียวกันไปที่คนเดิม วันใหม่จึงวนไปคนถัดไป (ค่าเริ่มต้นทุกเทคนิคเป็นทุกเคส)
6. ตั้งตำแหน่งคิวของแต่ละเทคนิคเองได้ในหน้าตั้งค่า (เหมือนเว้นแถวหรือสลับชื่อในไฟล์เดิม)
7. เลือกหลายเทคนิคในครั้งเดียว เทคนิคแรกเดินคิวตามปกติ เทคนิคถัดไปให้คนเดียวกัน (`follow`) คิวไม่ขยับและหักคิวคนนั้น 1 ครั้งเมื่อวนมาถึง เหมือนข้อ 3
8. บน Google Sheet ระบบเลือกคนรับเคสฝั่งเซิร์ฟเวอร์ภายใต้ล็อก ถ้าสองคนกดแจกเคสพร้อมกันก็จะไม่ได้คนเดียวกัน
   เคสหลายเทคนิคบันทึกพร้อมกันทั้งชุด ถ้าเทคนิคใดแจกไม่ได้ (เช่น ทุกคนลา) จะไม่บันทึกเคสใดในชุดนั้นเลย

ทดสอบโดยนำเข้าข้อมูลเดือนตุลาคม 2569 จากไฟล์เดิมแล้ว คะแนนรวมของทุกคนตรงกับแท็บ P4P ถึงทศนิยมตำแหน่งที่ 3

## ติดตั้งกับ Google Sheet

1. เปิดไฟล์ `P4P_Physics` ใน Google Sheets (หรือสำเนาของไฟล์)
2. เมนู **ส่วนขยาย → Apps Script**
3. ในไฟล์ `Code.gs` ให้ลบโค้ดเดิมแล้ววางเนื้อหาจาก [`Code.gs`](Code.gs)
4. หน้าเว็บ (`index.html`) **โหลดจาก GitHub อัตโนมัติ** (`PAGE_URL` ใน `Code.gs` เก็บไว้ 10 นาที) ไม่ต้องวาง
   ถ้าต้องการสำรองไว้ในโปรเจกต์ กด **＋ → HTML** ตั้งชื่อ `index` แล้ววาง [`index.html`](index.html) ระบบใช้ไฟล์นี้เมื่อโหลดจาก GitHub ไม่ได้
5. กดบันทึก แล้วกลับไปที่ชีตและรีเฟรชหน้า จะมีเมนู **ระบบกระจายงาน** เพิ่มขึ้น
6. เลือก **ระบบกระจายงาน → นำเข้าข้อมูลจากแท็บเดิม** (ครั้งแรก Google จะขอสิทธิ์ ให้กดอนุญาต)
   ระบบจะสร้างแท็บ `Cases`, `Logs`, `Leaves`, `Config` และตั้งคิวถัดไปให้ตรงกับแถวว่างในแท็บเดิม รันซ้ำได้โดยไม่เพิ่มรายการซ้ำ
7. ใช้งานได้สองแบบ
   - **ในชีต** (เจ้าของไฟล์และแอดมิน): ระบบกระจายงาน → เปิดระบบ
   - **เป็นเว็บ (ใช้บนมือถือได้)**: ใน Apps Script กด **การทำให้ใช้งานได้ → การทำให้ใช้งานได้รายการใหม่ → เว็บแอป**
     - ดำเนินการในฐานะ: **ฉัน (Me)** · ผู้ที่มีสิทธิ์เข้าถึง: **ทุกคน (Anyone)**
     - ทุกคนเข้าสู่ระบบด้วยบัญชี LPCH RO Workspace ไม่ต้องแชร์ชีตให้ทีม (สคริปต์อ่านเขียนชีตในนามเจ้าของ)
8. เลือกฟังก์ชัน **`checkSetup`** แล้วกด **เรียกใช้** (ตรวจหน้าเว็บจาก GitHub, LPCH และชีตในครั้งเดียว) (อนุญาต "เชื่อมต่อกับบริการภายนอก") บันทึกการทำงานต้องขึ้น
   `✓ เชื่อมต่อ LPCH RO Workspace ได้ และรองรับการใช้บัญชีร่วมกันแล้ว`
9. ใน LPCH RO Workspace (บัญชีผู้ดูแลระบบ) เพิ่มปุ่มหรือการ์ดแอปที่ลิงก์ไป URL `/exec` ของระบบนี้ และติ๊ก **เข้าสู่ระบบอัตโนมัติ**
   กดแล้วจะเข้าระบบนี้ด้วยบัญชี LPCH ทันที

### ใช้โปรเจกต์ Apps Script แยก (ไม่ได้เปิดจากชีต)

ถ้าสร้างโปรเจกต์จาก script.google.com โดยตรง สคริปต์ไม่ได้ผูกกับชีตใด ระบบจะเลือกชีตเก็บข้อมูลตามลำดับนี้

1. ชีตใน Script property **`SHEET_ID`** (การตั้งค่าโปรเจกต์ → คุณสมบัติของสคริปต์) ใส่ได้ทั้ง ID หรือลิงก์ของชีต
   เช่น ลิงก์ของไฟล์ `P4P_Physics` แล้วรันฟังก์ชัน **`importLegacy`** จากหน้าแก้ไขสคริปต์เพื่อนำเข้าข้อมูลเดิม (ผลอยู่ในบันทึกการทำงาน)
2. ถ้ายังไม่ได้ตั้ง ระบบสร้างชีตใหม่ชื่อ **ระบบกระจายงานฟิสิกส์การแพทย์ (ข้อมูล)** ใน Google Drive ของบัญชีที่ Deploy ให้ครั้งแรก
   แล้วจำไว้ใน `SHEET_ID` เอง ดูลิงก์ชีตได้จาก `checkSetup` หรือ ตั้งค่า → เปิด Google Sheet

ใช้ `SHEET_ID` ไม่ได้ (ลิงก์ผิดหรือบัญชีที่ Deploy เปิดชีตนั้นไม่ได้) หน้าเว็บจะแจ้งสาเหตุ ระบบจะไม่สร้างชีตใหม่แทน

### เข้าสู่ระบบด้วยบัญชี LPCH RO Workspace

- **กดจาก LPCH**: ลิงก์แนบบัตรผ่าน (`?sso=…`) ใช้ได้ครั้งเดียว อายุ 2 นาที เข้าสู่ระบบให้ทันที
- **เปิด URL ของระบบนี้ตรง ๆ**: หน้าแรกเป็นช่องชื่อผู้ใช้หรืออีเมล + รหัสผ่านของ LPCH (ตรวจที่ LPCH ระบบนี้ไม่เก็บรหัสผ่าน)
  พร้อมปุ่มไปที่ LPCH RO Workspace
- **เว็บใช้บัญชี LPCH เสมอ รวมเจ้าของไฟล์** บัญชี Google ใช้ได้เฉพาะ ระบบกระจายงาน → เปิดระบบ ในชีต (เจ้าของไฟล์และแอดมิน)
- มุมขวาบนมีปุ่ม **Home** กลับหน้าหลัก LPCH RO Workspace ชื่อและตำแหน่งของคนที่เข้าสู่ระบบ และปุ่ม **ออกจากระบบ**
- **สิทธิ์**
  - **MP** บันทึกข้อมูลได้ทุกอย่าง: แจกเคส Finish/Evaluate RC กิจกรรม และวันลา
  - **ตำแหน่งอื่น** (RO, RTT, Nurse, Other) **ดูได้อย่างเดียว** เฉพาะแถบที่แอดมินติ๊ก "ตำแหน่งอื่น" ใน ตั้งค่า → แถบเมนู ไม่มีฟอร์มและปุ่มบันทึก
  - **แอดมิน** (แก้การตั้งค่า): MP ที่เป็นผู้ดูแลระบบของ LPCH หรือ MP ที่ใส่ชื่อผู้ใช้/อีเมลไว้ใน ตั้งค่า → แอดมิน
  - เปลี่ยนตำแหน่งที่บันทึกได้ที่ `LPCH_EDIT_ROLES` ใน `Code.gs` (ค่าเริ่มต้น `['MP']`)
- ตรวจบัญชีกับ LPCH ทุกครั้งที่ใช้ (เก็บผลไว้ 5 นาที) ระงับบัญชีหรือเปลี่ยนตำแหน่งใน LPCH มีผลที่นี่ภายใน 5 นาที
- ฝั่ง Apps Script ตรวจสิทธิ์ทุกคำสั่ง ผู้ที่ดูได้อย่างเดียวเรียก API เองก็บันทึกไม่ได้
- URL ของ LPCH อยู่ที่ `LPCH_URL` ใน `Code.gs` เปลี่ยนได้ที่ Script property `LPCH_URL` (ใส่ `-` เพื่อปิดและใช้บัญชี Google แบบเดิม)

### แอดมิน

- **เจ้าของไฟล์ Google Sheet เป็นแอดมินเสมอ** เมื่อเปิดด้วยบัญชี Google (จากเมนูในชีต) ใช้ตั้งค่าครั้งแรกและนำเข้าข้อมูล
- MP ที่เป็นผู้ดูแลระบบของ LPCH เป็นแอดมินที่นี่อัตโนมัติ เพิ่ม MP คนอื่นได้ที่ ตั้งค่า → แอดมิน (ชื่อผู้ใช้หรืออีเมล LPCH)
- ระบบตรวจสิทธิ์ทั้งบนหน้าเว็บและฝั่ง Apps Script (`saveConfig`, `importLegacy`) ผู้ที่ไม่ใช่แอดมินเรียกตรงก็บันทึกการตั้งค่าไม่ได้
- ระบบไม่ให้บันทึกรายชื่อแอดมินที่ไม่มีชื่อของตัวเอง กันล็อกตัวเองออก
- เมื่อ Deploy แบบ Execute as Me ไม่ต้องแชร์ชีตให้ใคร คนที่มีสิทธิ์แก้ไขชีตโดยตรงยังแก้แท็บต่าง ๆ ได้เอง จึงแชร์เฉพาะคนที่ไว้ใจ

- ถ้าโหลดหน้าเว็บจาก GitHub ไม่ได้และไฟล์ index ในโปรเจกต์เป็นรุ่นเก่า หน้าเว็บจะมีแถบสีเหลืองบอกสาเหตุ
- อย่ากด "การทำให้ใช้งานได้รายการใหม่" ตอนอัปเดต เพราะจะได้ URL ใหม่ ลิงก์เดิมและปุ่มใน LPCH ยังเปิดรุ่นเก่า
- บรรทัดล่างสุดของหน้าบอก **รุ่นหน้าเว็บ · ที่มาของหน้าเว็บ (GitHub / ไฟล์ index) · รุ่น Code.gs**
  ถ้า Code.gs เก่ากว่าที่หน้าเว็บต้องการ (`API_LEVEL`) จะมีแถบเตือนให้วาง Code.gs ใหม่
- เปลี่ยนที่มาของหน้าเว็บได้ที่ Script property `PAGE_URL` (ใส่ `-` เพื่อใช้ไฟล์ index ในโปรเจกต์เท่านั้น)
  หน้าเว็บจาก GitHub ทำงานด้วยสิทธิ์ของสคริปต์นี้ ใครที่ push เข้า branch นั้นได้จึงเปลี่ยนหน้าเว็บได้ ให้สิทธิ์ repo เฉพาะคนที่ไว้ใจ
- **ถ้าหน้าเว็บเริ่มทำงานไม่ได้** จะมีกล่องสีแดงบอกสาเหตุแทนหน้าว่าง (สคริปต์ผิดพลาดพร้อมบรรทัด หรือได้รับหน้าเว็บมาไม่ครบ)
  ถ้าโค้ดที่ Google ส่งมาอ่านไม่ได้ หน้าเว็บจะใช้ต้นฉบับรุ่นเดียวกันจาก GitHub แทน และมีแถบสีเหลืองบอกบรรทัดที่เสีย
- **สำหรับผู้แก้โค้ด**: Apps Script ตัดคอมเมนต์ในสคริปต์ก่อนส่งหน้าเว็บ และตัวตัดของมันอาจตัด `//…` ที่อยู่ในสตริงทิ้งด้วย
  (เคยทำให้หน้าเว็บเปิดไม่ได้) จึงห้ามมี `//`, `/*`, `*/` ในสตริง เทมเพลต หรือ regex ในสคริปต์ของหน้าเว็บ
  ลิงก์ให้เขียน `'https:\/\/…'` แทน `'https://…'`

## ลองใช้โดยไม่ต้องติดตั้ง

เปิด `index.html` ในเบราว์เซอร์ได้เลย ระบบจะเข้าโหมดตัวอย่างพร้อมเคสสมมติ (HN ขึ้นต้นด้วย 999)
ข้อมูลในโหมดนี้เก็บไว้ในเบราว์เซอร์เครื่องนั้นเท่านั้น หน้าตั้งค่ามีปุ่มสลับมุมมอง "MP · แอดมิน / MP / ตำแหน่งอื่น" ให้ลองดูหน้าจอของแต่ละสิทธิ์

## โครงสร้างข้อมูลในชีต

| แท็บ | เนื้อหา |
| --- | --- |
| `Cases` | id, หมวด, MP, วิธีแจก (`auto` / `manual` / `follow` = ตามเทคนิคแรก), จำนวนครั้ง (ว่าง = 1), CT-Sim, In, Sim, Finish, Evaluate, Type, HN, Name, ICD-10, Diagnosis, Doc, Aim, Technique, ห้องฉาย, Dose/fx (Gy), Fx, ความถี่, บริเวณที่ฉาย, บริเวณเพิ่มเติม (บริเวณที่ 2 เป็นต้นไป, JSON), ชุด (เคสที่แจกพร้อมกันหลายเทคนิค), Note และคอลัมน์ของหัวข้อเพิ่มเติม |
| `Logs` | id, ประเภท (`rc` / `dqa` / `brachy` / `brachyn` / `p2h` / `hyper` / `acad` / `admin` / กิจกรรมที่เพิ่มเอง), Date, MP, HN, Name, เคส (id), กิจกรรม, เวลา, k, Note |
| `Leaves` | id, MP, ตั้งแต่, ถึง, Note |
| `Config` | ทีมและประวัติตำแหน่ง, ตำแหน่งและแต้ม, แพทย์, คนถัดไปที่ตั้งเอง, เวลาและน้ำหนักของแต่ละหมวด, ตัวเลือกในฟอร์ม, หัวข้อเพิ่มเติม, ช่องบังคับกรอก, ค่าเริ่มต้นในฟอร์ม, อีเมลแอดมิน, แต้มต่อรายเดือน (JSON) |

ข้อมูลทั้งหมดเป็นข้อความล้วน เพิ่มคอลัมน์ของตัวเองต่อท้ายได้ ระบบจะไม่เขียนทับ

## ความเป็นส่วนตัว

ข้อมูลผู้ป่วย (HN, ชื่อ) อยู่ใน Google Sheet ของโรงพยาบาลเท่านั้น โค้ดในโฟลเดอร์นี้ไม่มีข้อมูลผู้ป่วยจริง
แม้ Deploy แบบ Anyone คนที่ยังไม่เข้าสู่ระบบด้วยบัญชี LPCH จะเห็นแค่ช่องเข้าสู่ระบบ เซิร์ฟเวอร์ไม่ส่งข้อมูลให้
