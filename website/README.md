# LPCH RO Workspace

เว็บไซต์พื้นที่ทำงานกลางของหน่วยรังสีรักษา (Radiation Oncology) — static site (HTML/CSS/JS ล้วน ไม่ต้อง build)

## หน้าตา (Design)

ใช้ design เดียวกับเว็บ **TRS-398 Output Calibration** ของโรงพยาบาลมะเร็งลำปาง (`trs398-calculator/index.html`)

- ฟอนต์: **Chakra Petch** (หัวข้อ), **IBM Plex Sans Thai** (เนื้อหา), **IBM Plex Mono** (ตัวเลข)
- สีหลัก: Cherenkov blue `#1d5bd6`, พื้นหลัง `#eef2f6`, ตัวอักษร `#142033` พร้อมโหมดกลางคืน (สลับ อัตโนมัติ / กลางวัน / กลางคืน ที่มุมขวาบน)
- หัวเว็บ: โลโก้โรงพยาบาลบนกรอบสีขาว + ชื่อ "LPCH **RO Workspace**" + Lampang Cancer Hospital (แก้ได้ที่ `brand` ใน `data.js`)
- โลโก้: `assets/lpch-emblem.png` (หัวเว็บ, หน้าเข้าสู่ระบบ) และ `assets/lpch-logo.png` (ท้ายเว็บ)
- สีทั้งหมดกำหนดเป็นตัวแปรที่ต้นไฟล์ `styles.css`

## ระบบสมาชิก (ต้องสมัครก่อนใช้งาน)

ทุกหน้าของเว็บไซต์ต้องเข้าสู่ระบบก่อน ผู้ใช้ใหม่กด **สมัครสมาชิก** กรอก ชื่อ-นามสกุล, ตำแหน่ง (RO / MP / RTT / Nurse / อื่นๆ),
ชื่อผู้ใช้, **อีเมล (บังคับ, 1 อีเมลต่อ 1 บัญชี)**, รหัสผ่าน (≥ 8 ตัว) และเบอร์โทร

- **ผู้สมัครคนแรก** จะเป็นผู้ดูแลระบบ (admin) และเข้าใช้งานได้ทันที
- ผู้สมัครคนต่อไปมีสถานะ **รออนุมัติ** จนกว่า admin จะอนุมัติที่เมนูผู้ใช้ (มุมขวาบน) → **จัดการสมาชิก**
- admin อนุมัติ / ระงับ / ลบบัญชี, เปลี่ยนตำแหน่ง และตั้งผู้ดูแลระบบเพิ่มได้
- สมาชิกแก้ไขอีเมล/เบอร์โทร และเปลี่ยนรหัสผ่านได้ที่ **บัญชีของฉัน**
- บัญชีเก่าที่ยังไม่มีอีเมล จะถูกพาไปหน้า **บัญชีของฉัน** หลังเข้าสู่ระบบเพื่อเพิ่มอีเมล
- **ลืมรหัสผ่าน** (ลิงก์ใต้ปุ่มเข้าสู่ระบบ):
  1. กรอกชื่อผู้ใช้หรืออีเมล → ระบบส่ง **รหัสยืนยัน 6 หลัก** ไปที่อีเมลของบัญชี (ส่งจาก Gmail ของเจ้าของสคริปต์ผ่าน MailApp)
  2. กรอกรหัส + รหัสผ่านใหม่ → เข้าสู่ระบบด้วยรหัสผ่านใหม่
  - รหัสหมดอายุใน 15 นาที, ใส่ผิดได้ 5 ครั้ง, ขอรหัสได้ 3 ครั้งต่อ 15 นาที, หลังตั้งรหัสใหม่ทุก session เดิมของบัญชีจะถูกออกจากระบบ
  - ระบบไม่เก็บรหัสผ่านจริง จึงส่งรหัสยืนยันแทนการส่งรหัสผ่านเดิม และตอบข้อความเดียวกันเสมอเพื่อไม่บอกว่าอีเมลใดมีบัญชี
  - Gmail ส่วนตัวส่งอีเมลได้ประมาณ 100 ฉบับต่อวัน (ดูโควตาที่เหลือได้จาก log ของฟังก์ชัน `setup`)
  - โหมดทดลองส่งอีเมลไม่ได้ จะแสดงรหัสบนหน้าจอแทน
- ช่องแชทประกาศใช้ชื่อและตำแหน่งของผู้ที่เข้าสู่ระบบโดยอัตโนมัติ
- ใส่รหัสผ่านผิด 5 ครั้งจะถูกล็อก 15 นาที, session หมดอายุใน 7 วัน

### ติดตั้งเป็น Google Apps Script web app (แนะนำ)

ไฟล์สำหรับ Apps Script อยู่ในโฟลเดอร์ `apps-script/`:

| ไฟล์ | หน้าที่ |
| --- | --- |
| `apps-script/Code.gs` | เซิร์ฟเวอร์: แสดงหน้าเว็บ, ระบบสมาชิก, แชทประกาศ (เก็บใน Google Sheets), รูปแนบ (เก็บใน Google Drive) |
| `apps-script/Index.html` | หน้าเว็บทั้งหมดในไฟล์เดียว (CSS, JavaScript, โลโก้ รวมอยู่ในไฟล์) |

ขั้นตอน:

1. สร้าง Google Sheet ใหม่ (เช่น "LPCH RO Workspace Data") → เมนู **Extensions → Apps Script**
2. เปิดไฟล์ Code.gs ฉบับเต็มจาก
   <https://raw.githubusercontent.com/nattayee/nattayee/refs/heads/claude/lpch-ro-workspace-website-96j4r6/website/apps-script/Code.gs>
   กด Ctrl+A (มือถือ: เลือกทั้งหมด) → คัดลอก → ลบโค้ดเดิมใน Apps Script แล้ววาง → Save
   ตรวจว่าบรรทัดสุดท้ายคือ `// ----- สิ้นสุดไฟล์ Code.gs ...` (ถ้าไม่มี แสดงว่าวางไม่ครบ และจะขึ้น SyntaxError: Unexpected end of input)
   **ถ้าคัดลอกแล้วได้แค่ 100 บรรทัด** (Apps Script ขึ้น `SyntaxError: Unexpected end of input บรรทัด: 100`)
   แสดงว่าที่ที่คัดลอกมาส่งให้แค่ส่วนต้นของไฟล์ ให้ใช้หน้า "คัดลอก Code.gs" (กล่องโค้ดพร้อมปุ่มคัดลอกทั้งหมด) ที่ส่งให้ในแชท
   หรือเปิดลิงก์ raw ด้านบนแล้วกด Ctrl+A
3. **ไม่ต้องวาง Index.html** — Code.gs โหลดหน้าเว็บจาก GitHub ให้เอง (`PAGE_URL`, cache 10 นาที)
   ถ้าต้องการเก็บหน้าเว็บไว้ในโปรเจกต์: กด **+ → HTML** ตั้งชื่อ `Index` แล้ววาง `apps-script/Index.html` (จะใช้ไฟล์นี้ก่อน)
   ถ้าไฟล์ `Index`/`index` ในโปรเจกต์วางมาไม่ครบ (ไม่มี `</html>` ท้ายไฟล์) ระบบจะไม่ใช้ไฟล์นั้นและโหลดจาก GitHub แทน — ลบทิ้งได้เลย
4. เลือกฟังก์ชัน `setup` ที่แถบด้านบน → **Run** → อนุญาตสิทธิ์ (Google Sheets, Google Drive, ส่งอีเมล, เชื่อมต่อบริการภายนอก) — ระบบสร้างชีตและโฟลเดอร์รูปให้
5. **Deploy → New deployment** → ประเภท **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
6. กด Deploy แล้วเปิด **Web app URL** (ลงท้ายด้วย `/exec`) → สมัครบัญชีแรก (จะได้เป็น admin)

ข้อมูลที่ระบบสร้างใน Google Sheet:

| ชีต | เก็บอะไร |
| --- | --- |
| `Users` | สมาชิก (รหัสผ่านเก็บแบบ hash SHA-256 + salt ไม่เก็บรหัสจริง) |
| `Sessions` | การเข้าสู่ระบบ (หมดอายุ 7 วัน) |
| `Messages` | ข้อความแชท (1 แถวต่อข้อความ รวมสถานะอ่าน / ✓ ✗ / ส่งต่อ) |
| `DirectMessages` | ข้อความส่วนตัว (1 แถวต่อข้อความ รวมเวลาอ่านและการกด ✓ ✗) |
| `Settings` | ข้อความด่วน (Quick chat) ของแต่ละคน — 1 แถวต่อสมาชิก |
| `Status` | สถานะของแต่ละคน (สถานะ, สถานที่, ข้อความสั้น, เวลาอัปเดต) — 1 แถวต่อสมาชิก |
| `Config` | ตัวเลือกสถานะ รายชื่อสถานที่ / เครื่อง และรายการปฏิทินหน้าแรก ที่ผู้ดูแลระบบตั้ง |
| `Menus` | เมนูย่อยที่ผู้ดูแลระบบเพิ่มเอง (1 แถวต่อเมนู), ชื่อใหม่ / การซ่อนเมนูเดิม และลำดับเมนูของแต่ละหัวข้อ |
| `ChatLog` | **บันทึกทุกการกระทำ**: ส่ง, ตอบกลับ, อ่าน, ✓ ถูก / ✗ ผิด, ส่งต่อ, ลบ พร้อมวันที่เวลา (เวลาไทย) และผู้กระทำ |

รูปที่แนบในแชทเก็บในโฟลเดอร์ Google Drive `LPCH RO Workspace Images` ของเจ้าของสคริปต์ ไม่ได้แชร์สาธารณะ
หน้าเว็บโหลดรูปผ่านเซิร์ฟเวอร์เฉพาะผู้ที่เข้าสู่ระบบ ข้อความใหม่จะแสดงอัตโนมัติทุก 15 วินาที (ตั้งได้ที่ `chat.pollSeconds` ใน `data.js`)

ในโหมดนี้ ชื่อผู้ส่ง ผู้อ่าน และผู้กด ✓/✗ มาจาก session ฝั่งเซิร์ฟเวอร์ ปลอมแปลงจากหน้าเว็บไม่ได้
ลบข้อความได้เฉพาะ admin

**อัปเดตภายหลัง:** แก้ไฟล์ใน `website/` แล้วรัน `python3 website/build_apps_script.py` เพื่อสร้าง `apps-script/Index.html` ใหม่ แล้ว push ขึ้น GitHub
หน้าเว็บใน Apps Script จะเปลี่ยนเองภายใน 10 นาที ไม่ต้อง Deploy ใหม่ (ถ้าใช้ไฟล์ `Index` ในโปรเจกต์ ต้องวางทับเอง)
ถ้าแก้ `Code.gs` ต้องวางใหม่ → Run `setup` อีกครั้งถ้ามีสิทธิ์ใหม่ → **Deploy → Manage deployments → ✏️ Edit → Version: New version → Deploy** (URL เดิมใช้ต่อได้)
หมายเหตุ: `PAGE_URL` ชี้ไปที่ branch `claude/lpch-ro-workspace-website-96j4r6` — ถ้าย้ายไป branch อื่นให้แก้ค่านี้ใน Code.gs

ตั้งค่าเพิ่มเติมได้ที่ต้นไฟล์ `Code.gs`: `REQUIRE_APPROVAL` (ปิดการอนุมัติ), `SESSION_DAYS`, `ROLES`, `CHAT_LIMIT`

### ใช้กับเว็บ static ที่อื่น (ทางเลือก)

ถ้าวางโฟลเดอร์ `website/` บน GitHub Pages หรือ web server อื่น ให้ใส่ URL `/exec` ของ deployment ข้างบนที่ `auth.apiUrl` ใน `data.js`
ระบบสมาชิกและแชทจะใช้ Google Sheet เดียวกัน

> ถ้ายังไม่ได้ใส่ `auth.apiUrl` ระบบจะอยู่ใน **โหมดทดลอง** — สมาชิกเก็บในเบราว์เซอร์นี้เท่านั้น ใช้สำหรับทดลองหน้าตาเท่านั้น
>
> **ข้อจำกัด:** หน้าเว็บนี้เป็น static site การล็อกอินจึงซ่อนหน้าจอจากผู้ที่ไม่ได้เป็นสมาชิก แต่ไฟล์ `data.js` (ลิงก์เอกสาร) ยังเปิดอ่านได้ถ้ารู้ URL
> เอกสารสำคัญควรตั้งสิทธิ์การเข้าถึงใน Google Drive ให้เฉพาะบัญชีของหน่วยงานด้วย

## แก้ไขเนื้อหา

เนื้อหาทั้งหมดอยู่ใน **`data.js`** ไฟล์เดียว:

- เมนูด้านบนกำหนดที่ `nav` (เพิ่ม `children` เพื่อทำ dropdown) และเนื้อหาแต่ละหน้าอยู่ที่ `pages`
- ลิงก์ที่เป็น `"#"` คือ placeholder (จะแสดงเป็น "รอใส่ลิงก์") ให้แทนด้วยลิงก์ Google Drive / Docs / Forms จริง
- เว็บแอปที่ใช้ประจำใส่ใน `apps` ของหน้า (การ์ดใหญ่พร้อมปุ่ม **เปิดแอป ↗** เช่น TRS-398 ในหน้า `mp/dosimetry`) — เปิดในแท็บใหม่
  เพราะแอป Apps Script อื่นฝังในหน้านี้ไม่ได้ (Google บล็อกการฝังถ้าแอปนั้นไม่ได้ตั้ง `ALLOWALL`) และต้องล็อกอิน Google ของแอปนั้นเอง
- แต่ละหน้ามี `groups` (กล่องรายการลิงก์) และ `widgets` (`calculators`, `constraints`, `subpages` ฯลฯ)

## Pop up แจ้งเตือนข้อความใหม่

ทำงานทุกหน้าหลังเข้าสู่ระบบ (โค้ดใน `notify.js`, ตรวจทุก `chat.notifySeconds` = 20 วินาที)

- **แชทประกาศ**: ข้อความใหม่ที่ส่งถึงทุกคน / วิชาชีพของผู้ใช้ / ผู้ใช้โดยตรง หรือมีคน**ส่งต่อ**มาให้ — "📣 ประกาศถึงคุณจาก …"
- **ข้อความส่วนตัว**: "✉️ ข้อความส่วนตัวจาก …"
- pop up มุมขวาล่าง แสดงผู้ส่ง ตัวอย่างข้อความ เวลา ปุ่ม **เปิดดู** (พาไปที่ข้อความนั้นและไฮไลต์ / เปิดบทสนทนา) และ **ปิด**
- เสียงเตือนสั้นๆ (ปิด/เปิดได้ที่เมนูผู้ใช้ → 🔔 เสียงแจ้งเตือน), ตัวเลขบนแท็บเบราว์เซอร์เมื่อดูแท็บอื่นอยู่
- ตัวเลขข้อความที่ยังไม่อ่าน: บนแท็บ **💬 แชท** (ประกาศ) และปุ่ม **✉️ ข้อความ** (ข้อความส่วนตัว)
- ตอนเข้าสู่ระบบ ถ้ามีข้อความค้างอ่าน จะแจ้งสรุปหนึ่งครั้ง
- เด้งทุกครั้งที่มีข้อความใหม่ถึงผู้ใช้ รวมถึงตอนเปิดแท็บแชทอยู่ (แม้หน้าแชทจะบันทึกว่าอ่านแล้ว) ยกเว้นข้อความส่วนตัวในบทสนทนาที่เปิดดูอยู่
  และไม่แจ้งข้อความที่ตัวเองส่ง
- ถ้า `Code.gs` ที่ Deploy ไว้ยังเป็นเวอร์ชันเก่า (ไม่มีคำสั่ง `notify`) จะขึ้น pop up "ระบบแจ้งเตือนยังไม่พร้อม" ให้ผู้ดูแลอัปเดต
- เมนูผู้ใช้ → **📲 เปิดการแจ้งเตือนบนเครื่อง** เพื่อให้เบราว์เซอร์แจ้งเตือนแม้ดูแท็บอื่น
  (เบราว์เซอร์บางตัวไม่อนุญาตในหน้า Apps Script — pop up ในหน้าเว็บยังทำงานตามปกติ)

## ข้อความส่วนตัว (Inbox)

ปุ่ม **✉️ ข้อความ** มุมขวาบน (มีตัวเลขข้อความที่ยังไม่อ่าน) หรือเมนูผู้ใช้ → **ข้อความส่วนตัว** (`#/inbox`) — โค้ดใน `dm.js`

- ส่งข้อความ**ตัวต่อตัว**ระหว่างสมาชิก: กด **+ ข้อความใหม่** → เลือกชื่อ (แยกตามวิชาชีพ ค้นหาได้)
- แนบรูปได้ 4 รูป (📎, Ctrl+V, ลากวาง), **↩ ตอบกลับ** อ้างอิงข้อความ
- **ลบ** ได้เฉพาะ admin และเฉพาะในบทสนทนาที่ admin อยู่ด้วย (admin มองไม่เห็นบทสนทนาของคนอื่น)
- **✓ ถูก / ✗ ผิด** กดได้เฉพาะผู้รับข้อความนั้น (ผู้ส่งกดไม่ได้) แสดงชื่อผู้กดและวันที่เวลาใต้ข้อความ
- สถานะ: `✓ ส่งแล้ว` / `✓✓ อ่านแล้ว 10:32` และ **รายละเอียด ▾** แสดงเวลาส่ง เวลาอ่าน และการกด ✓/✗ พร้อมวันที่เวลา
- ลิงก์ตรงไปบทสนทนา: `#/inbox?u=<username>`
- **เห็นเฉพาะผู้ส่งและผู้รับ** — เซิร์ฟเวอร์ตรวจสิทธิ์ทุกคำขอ admin ในเว็บก็อ่านไม่ได้ รูปเก็บแยกในโฟลเดอร์ Drive
  `LPCH RO Workspace Private Images` และเปิดได้เฉพาะ 2 คนในบทสนทนา ข้อความส่วนตัวไม่ถูกบันทึกลง `ChatLog`
- หมายเหตุ: เจ้าของ Google Sheet/Drive (บัญชีที่ Deploy สคริปต์) ยังเปิดชีต `DirectMessages` ได้โดยตรงในฐานะเจ้าของไฟล์

## ปฏิทินในหน้าแรก

โค้ดใน `calendars.js` — ใต้ปุ่ม Workspace มีส่วน **ปฏิทิน** ฝังเว็บแอปปฏิทิน / นัดคิว (หรือ Google Calendar แบบ embed) ไว้ในหน้าเว็บ

- มีหลายปฏิทินจะแสดงเป็น **แท็บ** ให้เลือก (จำแท็บล่าสุดไว้; สลับแท็บไม่ต้องโหลดใหม่) และมีปุ่ม **เปิดในแท็บใหม่ ↗** เสมอ
- ผู้ดูแลระบบกด **⚙️ ตั้งค่าปฏิทิน**: เพิ่ม / แก้ชื่อแท็บ / ลิงก์ / ความสูง / เรียงลำดับ / ลบ (สูงสุด 10)
  และติ๊ก "เข้าสู่ระบบอัตโนมัติ" ได้สำหรับเว็บแอป Apps Script ที่รองรับ `?sso=` (แบบ TRS-398 และ Linac QA)
- **เว็บแอป Apps Script จะแสดงในกรอบได้** ต่อเมื่อ `doGet` ของแอปนั้นคืนหน้าด้วย
  `.setXFrameOptionsMode(HtmlService.XFrameOptionsMode.ALLOWALL)` และ Deploy แบบ Who has access: **Anyone**
  (ถ้าต้องล็อกอิน Google ก่อน Google จะไม่ยอมให้แสดงในกรอบ — ใช้ปุ่มเปิดในแท็บใหม่แทน)
- เก็บในชีต `Config` แถว `calendars` (คำสั่ง `calendarsGet` / `calendarsSave` ใน `Code.gs`)

## บนโทรศัพท์

- หัวเว็บแบบแถวเดียว (โลโก้เล็ก, ปุ่มข้อความ, ปุ่มผู้ใช้) — เลือกโหมดสีได้ที่เมนูผู้ใช้ → **🌓 โหมดสี**
- **แถบล่างแบบแอป:** หน้าแรก · แชท · ข้อความ · ทีม (ไปที่สถานะทีม) · สถานะ (ตั้งสถานะของฉัน) พร้อมตัวเลขข้อความที่ยังไม่อ่าน
  ซ่อนอัตโนมัติในหน้าแชทและข้อความส่วนตัวเพื่อให้มีที่พิมพ์
- ปุ่ม Workspace และเมนูย่อยเรียง 2 ช่องต่อแถว · ปุ่มเล็ก ๆ ขยายให้กดง่ายบนจอสัมผัส

## สถานะทีม (อยู่ / ลา / ประชุม)

โค้ดใน `status.js`

- **ตั้งสถานะของฉัน:** ปุ่มข้างชื่อที่หัวเว็บ ("＋ ตั้งสถานะ" หรือสถานะปัจจุบัน), เมนูผู้ใช้ → **📍 ตั้งสถานะของฉัน** หรือปุ่มในแถบสถานะทีม
  เลือกสถานะ (อยู่ / ประชุม / ลา / …), **สถานที่** แยกกลุ่ม **เครื่อง** (Linac 1, Linac 2, CT Simulator, …) และ **ห้อง** (ห้องตรวจ OPD, ห้องวางแผนการรักษา, …)
  และข้อความสั้น ๆ (เช่น กลับ 13:00)
- **หน้า Home แถบขวา "สถานะทีม"** (แบบรายชื่อเพื่อนใน Facebook — บนมือถืออยู่ใต้เนื้อหาหลัก): ทุกคนเห็นสถานะ สถานที่ ข้อความ และเวลาอัปเดตของทุกคน
  จุดเขียว = เปิดเว็บอยู่ (ภายใน 2 นาที) · กรองตามสถานะ · ค้นหาชื่อ/ตำแหน่ง/สถานที่ · กดชื่อเพื่อส่งข้อความส่วนตัว · อัปเดตทุก 1 นาที
- **ผู้ดูแลระบบ:** ⚙️ ในแถบสถานะทีม หรือเมนูผู้ใช้ → **🏷️ ตั้งค่าสถานะ** (`#/status-settings`) เพิ่ม / ลบ / เรียงลำดับ / เปลี่ยนชื่อ ไอคอน และสีของตัวเลือกสถานะ
  และเพิ่ม / แก้ชื่อ / ลบ / เรียงลำดับ **เครื่อง** และ **ห้อง** (ในหน้าต่างสถานะของฉันมีลิงก์ ⚙️ แก้ไขรายการ สำหรับผู้ดูแลระบบ)
  — ลบตัวเลือกที่มีคนใช้อยู่ สถานะของคนนั้นจะเป็น "ไม่ระบุ"
- เก็บในชีต `Status` และ `Config` (คำสั่ง `statusList` / `statusSet` / `statusConfigSave` ใน `Code.gs`)

## จัดการเมนู (เฉพาะผู้ดูแลระบบ)

เมนูผู้ใช้ → **🧭 จัดการเมนู** (`#/menus`) หรือปุ่ม **＋ เพิ่มเมนูย่อยใน …** ที่หน้าหัวข้อหลัก — โค้ดใน `menus.js`

- เพิ่มเมนูย่อยใต้หัวข้อหลักได้ทุกหัวข้อ (Machines, RTT, Nurse, RO, MP, Guideline) แต่ละเมนูเป็นหน้าใหม่ที่มี
  ชื่อ, ไอคอน, คำอธิบาย, **การ์ดแอป** (ปุ่ม "เปิดแอป ↗") และ **รายการลิงก์** (ชื่อ, URL, ประเภท — เว้น URL ว่าง = "รอใส่ลิงก์")
- **เปลี่ยนชื่อ** และ **เลื่อนลำดับ ↑ ↓** ได้ทุกเมนู: หัวข้อหลักในแถบเมนู (Home และ แชท อยู่หน้าสุดเสมอ), เมนูย่อยเดิมของเว็บ
  และเมนูที่เพิ่มเอง (เรียงปนกันได้) — เปลี่ยนชื่อแล้วชื่อหน้า, breadcrumb และปุ่มในหน้า Home เปลี่ยนตาม; **คืนชื่อเดิม** ได้
- แก้ไขเนื้อหา / ลบ (กด 2 ครั้งเพื่อยืนยัน) เมนูที่เพิ่มเอง และ **ซ่อน / แสดง** เมนูย่อยเดิมของเว็บ
- **ปุ่ม Workspace ในหน้า Home** (การ์ดแรกของหน้าจัดการเมนู หรือปุ่ม **⚙️ จัดการปุ่ม Workspace** ในหน้า Home):
  แก้ชื่อ คำอธิบาย ไอคอน, เลื่อนลำดับ, ซ่อน / แสดงปุ่มเดิม (คืนค่าเดิมได้) และ **＋ เพิ่มปุ่ม** ไปหน้าในเว็บหรือลิงก์ภายนอก
  (ติ๊กเข้าสู่ระบบอัตโนมัติได้สำหรับเว็บแอป Apps Script) — ปุ่มเดิมที่ยังไม่ได้แก้ชื่อจะใช้ชื่อหัวข้อตามที่เปลี่ยนไว้
- หน้าที่เพิ่มเองมีปุ่ม **✏️ แก้ไขเมนูนี้** สำหรับผู้ดูแลระบบ
- หัวข้อที่ยังไม่มีเมนูย่อย (เช่น RTT) จะกลายเป็นเมนูแบบ dropdown และแสดงรายการเมนูย่อยในหน้าหัวข้อ
- การ์ดแอปติ๊ก "เข้าสู่ระบบให้อัตโนมัติ" ได้เฉพาะลิงก์เว็บแอป Apps Script (`https://script.google.com/macros/s/…/exec`) ที่เชื่อมบัญชีไว้แล้ว
  เช่น TRS-398 และ Linac QA (เพื่อไม่ให้บัตรเข้าสู่ระบบถูกส่งไปเว็บอื่น)
- เก็บในชีต `Menus` (คำสั่ง `menuList` / `menuSave` / `menuDelete` / `menuBuiltin` / `menuOrder` / `tileSave` ใน `Code.gs`) สมาชิกทุกคนเห็นเหมือนกัน
- เมนูและหน้าเดิมของเว็บยังแก้ที่ `data.js` เหมือนเดิม

## ใช้บัญชีร่วมกับแอป Linac QA และ TRS-398 Output Calibration

- หน้า **MP › Machine QA** (Linac QA) และ **MP › Dosimetry** (TRS-398) → **เปิดแอป ↗** เข้าแอปได้ทันทีโดยไม่ต้องกรอกรหัสอีก
  (ลิงก์แนบบัตรผ่านที่ใช้ได้ครั้งเดียว อายุ 2 นาที — คำสั่ง `ssoTicket` / `ssoRedeem` ใน `Code.gs`; ตั้ง `sso: true` ใน `data.js`)
- เปิดแอปตรง ๆ ก็ล็อกอินด้วยชื่อผู้ใช้ (หรืออีเมล) และรหัสผ่านเดียวกับเว็บนี้ได้ — รหัสผ่านเก็บที่ชีต `Users` ที่เดียว
- ใช้ได้เฉพาะ MP และผู้ดูแลระบบ (ตั้งที่ `LPCH_ROLES` ในโค้ดของแต่ละแอป) ระงับบัญชีที่นี่ก็เข้าแอปเหล่านั้นไม่ได้ด้วย
- ล็อกอินเว็บนี้ด้วยอีเมลแทนชื่อผู้ใช้ก็ได้
- ไฟล์และขั้นตอนติดตั้ง: [`linac-qa/README.md`](linac-qa/README.md) และ [`trs398/README.md`](trs398/README.md) (LPCH ต้อง Deploy แบบ Who has access: **Anyone**)

## ข้อความด่วน (Quick chat)

แถบ **⚡** เหนือช่องพิมพ์ในหน้า **💬 แชท** และ **ข้อความส่วนตัว** — โค้ดใน `quick.js`

- แตะปุ่มข้อความ → ข้อความถูกใส่ลงช่องพิมพ์ (แก้ไขต่อได้ แตะหลายปุ่มจะต่อท้ายกัน) แล้วกดส่งตามปกติ
- **ตั้งค่าเองได้ทุกคน สูงสุด 5 ข้อความ** (ยาวไม่เกิน 100 ตัวอักษรต่อข้อความ): กด **⚙** ท้ายแถบ หรือเมนูผู้ใช้ → **บัญชีของฉัน** → การ์ด **⚡ ข้อความด่วน**
  ช่องที่เว้นว่างจะไม่แสดง, ปุ่ม **ใช้ค่าเริ่มต้น** คืนค่าเดิม
- ค่าเริ่มต้น: รับทราบครับ/ค่ะ · ขอบคุณครับ/ค่ะ · กำลังดำเนินการ · เรียบร้อยแล้ว · ขอรายละเอียดเพิ่มเติม
- เก็บบนเซิร์ฟเวอร์ในชีต `Settings` (คำสั่ง `quickGet` / `quickSave` ใน `Code.gs`) จึงเหมือนกันทุกเครื่องที่ล็อกอิน; โหมดทดลองเก็บในเบราว์เซอร์

## ช่องแชทประกาศ / ข่าวสาร

อยู่ที่แท็บ **💬 แชท** (`#/chat`, โค้ดใน `chat.js`) — เมื่อใช้งานผ่าน Apps Script ข้อมูลเก็บใน Google Sheet (ดูด้านบน)

หน้าตาแบบแอปแชททั่วไป (LINE / Messenger) ทั้งแชทประกาศและข้อความส่วนตัว:
- ข้อความของตัวเองอยู่ขวา คนอื่นอยู่ซ้ายพร้อมรูปย่อชื่อ ข้อความต่อเนื่องจากคนเดิม (ภายใน 5 นาที) รวมกลุ่มกัน
- ป้ายแบ่งวัน (วันนี้ / เมื่อวาน / วันที่) เวลาอยู่ในฟองข้อความ ปุ่มต่างๆ เป็นไอคอนเล็กใต้ฟอง (↩ ตอบกลับ, ↪ ส่งต่อ, 🗑 ลบ, 👁 ผู้อ่าน)
- ช่องพิมพ์ทรงแคปซูลขยายตามข้อความ ปุ่มส่งวงกลม เลือกผู้รับเป็นแถบเลื่อนแนวนอน
- หน้าแชทเต็มความสูงจอ ไม่มีส่วนท้ายเว็บ และบนมือถือหัวเว็บย่อเหลือโลโก้ ชื่อ ปุ่มข้อความ และเมนูผู้ใช้

- พิมพ์ประกาศและแนบรูปได้สูงสุด 4 รูป (ปุ่ม 📎, วางด้วย Ctrl+V หรือลากไฟล์มาวาง) รูปจะถูกย่อขนาดอัตโนมัติ
- เลือก **ส่งถึง**: ทุกคน / ทั้งวิชาชีพ (RO / MP / RTT / Nurse) / **👤 รายบุคคล** (เลือกรายชื่อสมาชิกแยกตามวิชาชีพ) หรือผสมกันได้
- ปุ่มใต้แต่ละข้อความ
  - **✓ ถูก / ✗ ผิด** — **กดได้เฉพาะผู้ที่ได้รับข้อความ** (ผู้ส่งและคนที่ไม่ได้อยู่ในรายชื่อผู้รับกดไม่ได้ ตรวจทั้งหน้าเว็บและเซิร์ฟเวอร์)
    รายชื่อผู้กดพร้อมวันที่เวลาแสดงใต้ข้อความทันที บันทึกชื่อ ตำแหน่ง username เปลี่ยนคำตอบได้ และเก็บประวัติการเปลี่ยนไว้ทั้งหมด
  - **↩ ตอบกลับ** — ตอบข้อความนั้นโดยตรง (อ้างอิงข้อความต้นฉบับ กดที่กรอบอ้างอิงเพื่อเลื่อนไปยังต้นฉบับ) ผู้รับตั้งต้นเป็นผู้ส่งเดิม
  - **↪ ส่งต่อ** ให้กลุ่มหรือรายบุคคล
  - **ลบ** — **เฉพาะผู้ดูแลระบบ (admin)** เท่านั้น สมาชิกทั่วไปลบไม่ได้แม้เป็นข้อความของตัวเอง (การลบถูกบันทึกใน `ChatLog`)
  - **👁 อ่าน N · กด N ▾** — เปิดดูรายชื่อผู้กด ✓/✗ และผู้อ่าน พร้อมวันที่เวลา (ถึงวินาที)
- **สถานะ** ใต้แต่ละข้อความ
  - `✓ RTT` = ส่งถึงกลุ่มนี้แล้ว ยังไม่มีใครในกลุ่มอ่าน, `✓✓ RTT` (สีเขียว) = มีคนในกลุ่มนี้อ่านแล้ว
  - `✓ สมหญิง (RTT)` (กรอบเส้นประ) = ส่งถึงบุคคลนี้ ยังไม่อ่าน, `✓✓ สมหญิง (RTT)` = อ่านแล้ว
  - `↪ ชื่อ (ตำแหน่ง) ส่งต่อให้ ...` = ประวัติการส่งต่อ
- **⬇ บันทึก CSV** — ดาวน์โหลดบันทึกทุกการกระทำ (ส่ง, ตอบกลับ, อ่าน, ✓/✗, ส่งต่อ) พร้อมผู้กระทำ วันที่ เวลา เปิดด้วย Excel / Google Sheets ได้
- ระบบบันทึกว่า "อ่านแล้ว" เมื่อข้อความที่ส่งถึงกลุ่มของผู้ใช้แสดงบนจอ
- ตัวกรอง: ทั้งหมด / ส่งถึงฉัน (รวมที่ส่งถึงตัวเองโดยตรง) / ที่ฉันส่ง และป้าย "ยังไม่อ่าน N"

### ที่เก็บข้อความ

- เปิดผ่าน Apps Script หรือใส่ `auth.apiUrl` → เก็บใน Google Sheet (แนะนำ)
- ตั้งค่า Firebase → เก็บใน Cloud Firestore (ด้านล่าง)
- ไม่ได้ตั้งค่าอะไร → **โหมดทดลอง** ข้อความเก็บใน localStorage ของเบราว์เซอร์แต่ละเครื่อง (คนอื่นจะไม่เห็น)

เพื่อให้ทุกคนเห็นข้อความร่วมกันแบบ realtime ให้ใช้ **Cloud Firestore** (แพ็กเกจฟรี Spark เพียงพอ):

1. สร้างโปรเจกต์ที่ <https://console.firebase.google.com>
2. Build → Firestore Database → Create database
3. Project settings → Your apps → เพิ่ม Web app แล้วคัดลอกค่า `apiKey`, `authDomain`, `projectId`, `appId` มาใส่ที่ `chat.firebase` ใน `data.js`
4. ตั้ง Firestore rules (Firestore → Rules):

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /announcements/{id} {
      allow read: if true;
      allow create: if request.resource.data.keys().hasAll(['author', 'text', 'to', 'createdAt'])
                    && request.resource.data.text.size() < 5000;
      // หลังส่งแล้ว แก้ได้เฉพาะสถานะการอ่าน/ส่งต่อ/การกด ✓ ✗ ไม่สามารถแก้เนื้อหาได้
      allow update: if request.resource.data.diff(resource.data).affectedKeys()
                      .hasOnly(['reads', 'to', 'toNames', 'forwards', 'reactions', 'reactionLog']);
      allow delete: if true;
    }
  }
}
```

รูปแนบเก็บอยู่ในเอกสาร Firestore โดยตรง (ไม่ต้องใช้ Firebase Storage) จำกัดประมาณ 900 KB ต่อข้อความ

> **ความปลอดภัย:** แชทใช้ชื่อจากระบบสมาชิก แต่ Firestore rules ด้านบนไม่ได้ตรวจสอบ session ของ Apps Script
> ผู้ที่รู้ค่า config ของ Firebase จึงยังเขียนข้อมูลตรงเข้า Firestore ได้ ห้ามโพสต์ข้อมูลระบุตัวผู้ป่วย (ชื่อ, HN, รูปที่เห็นหน้า)

## เปิดดูในเครื่อง

เปิดไฟล์ `index.html` ด้วยเบราว์เซอร์ได้ทันที หรือรัน local server:

```bash
cd website
python3 -m http.server 8000
# แล้วเปิด http://localhost:8000
```

## Deploy

เป็น static site จึงนำโฟลเดอร์ `website/` ไปวางบน GitHub Pages, Netlify, Vercel หรือ web server ของโรงพยาบาลได้โดยตรง

> ข้อมูลทางคลินิกในเว็บไซต์ใช้เป็นแนวทางประกอบเท่านั้น โปรดตรวจสอบกับ protocol ของหน่วยงานทุกครั้ง
