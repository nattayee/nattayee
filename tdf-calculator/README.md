# TDF Dose Calculator

Web app สำหรับคำนวณ Time-Dose-Fractionation (TDF) ตามโมเดลของ Orton & Ellis สำหรับรังสีรักษา
เป็นไฟล์ static ทั้งหมด ไม่ต้อง build เปิด `index.html` ในเบราว์เซอร์ได้เลย

```bash
# เปิดผ่าน local server (ทางเลือก)
npx serve tdf-calculator
# รัน unit tests ของสูตรคำนวณ
node --test tdf-calculator/tdf.test.js
```

## Google Apps Script (เข้าสู่ระบบด้วยบัญชี LPCH RO Workspace)

โฟลเดอร์ `apps-script/` คือเวอร์ชันสำหรับ deploy เป็น Web app บน Google Apps Script
ใช้บัญชีผู้ใช้ของ LPCH RO Workspace ผ่าน JSON API (`doPost`) ที่ Workspace มีอยู่แล้ว **ไม่ต้องแก้โปรเจกต์ Workspace**

**โปรเจกต์ Apps Script ใช้ไฟล์เดียว คือ `Code.gs`** หน้าเว็บ (`apps-script/Index.html` ~130 KB) โหลดจาก GitHub (`PAGE_URL`)
และแคชไว้ 10 นาที จึงไม่มีปัญหาการวางไฟล์ใหญ่ไม่ครบในตัวแก้ไข และอัปเดตหน้าเว็บได้โดยไม่ต้องวางใหม่
(ไฟล์ `Index` ในโปรเจกต์ใช้เป็นสำรองเฉพาะเมื่อโหลดจาก GitHub ไม่ได้และไฟล์ครบเท่านั้น)

1. วาง `Code.gs` ในไฟล์ `Code` (รหัส.gs) ลบไฟล์ `Index` / `Tdf` เดิมออก
2. เลือกฟังก์ชัน `setup` แล้วกด Run หนึ่งครั้ง (อนุญาต Sheets, Drive และการเชื่อมต่อภายนอก)
3. Deploy → New deployment → Web app → Execute as: **Me**, Who has access: **Anyone** (อัปเดต: Manage deployments → New version)
4. ท้ายหน้าเว็บแสดง "เวอร์ชัน xxxxxxx" ให้ตรงกับ `copy-code.html` · หลังอัปเดตหน้าเว็บบน GitHub รัน `clearPageCache` เพื่อเห็นทันที

ถ้าสคริปต์ในหน้าเว็บไม่ทำงาน (เช่น ไฟล์ถูกตัด) จะมีแถบสีแดงแจ้งที่ด้านบนของหน้า แทนที่ปุ่มจะกดไม่ได้เงียบ ๆ
เปิด `copy-code.html` เพื่อคัดลอก `Code.gs` ด้วยปุ่มเดียว

### วิธีเข้าสู่ระบบ

| ทาง | การทำงาน |
|---|---|
| จาก Workspace (แนะนำ) | ผู้ดูแลระบบเพิ่มปุ่มในหน้า Home หรือการ์ดแอปในเมนู ใส่ URL `/exec` ของ TDF และเปิด "เข้าสู่ระบบอัตโนมัติ" → Workspace เปิด `…/exec?sso=<บัตร>` → TDF แลกบัตรด้วย `ssoRedeem` |
| เปิด TDF ตรง ๆ | กรอกชื่อผู้ใช้/อีเมล + รหัสผ่านของ Workspace → `login` |
| ครั้งถัดไป | ใช้ token ที่บันทึกในเบราว์เซอร์ ตรวจด้วย `me` (อายุตาม `SESSION_DAYS` ของ Workspace) |
| ออกจากระบบ | `logout` ลบ session ในชีต Sessions ของ Workspace |

บัตร SSO ใช้ได้ครั้งเดียว หน้าเว็บจึงลบ `?sso=` ออกจากแถบที่อยู่ทันทีหลังแลกบัตร
เปิดแท็บได้โดยตรงด้วย `?tab=frac`, `?tab=gap`, `?tab=brachy` หรือ `?tab=ref`

หน้าเครื่องคำนวณซ่อนไว้จนกว่าจะเข้าสู่ระบบ (สูตรคำนวณไม่ใช่ข้อมูลลับ จึงตรวจสิทธิ์ที่หน้าเว็บ)

`Index.html` สร้างจาก `index.html` และ `tdf.js` ถ้าแก้ไฟล์ต้นฉบับให้รัน `node tdf-calculator/build-apps-script.js` ใหม่

## ความสามารถ

| แท็บ | คำนวณ |
|---|---|
| **Fractionated** | TDF, TDF ต่อ fraction, X, overall time, NSD (ret), dose เทียบเท่า 2 Gy × 5/สัปดาห์ และเทียบ BED/EQD2 (LQ) |
| **Treatment gap** | หลาย course พร้อมช่วงพัก ใช้ decay factor `(T/(T+R))^0.11` กับ TDF สะสม, TDF ที่สูญเสีย, **physical dose ที่หายไปจากการพัก** (TDF ที่ลดลงแต่ละช่วงพัก ÷ TDF ต่อ fraction × Gy/fx ของช่วงก่อนพัก แสดงเด่นที่สุดบนหน้าผล และเป็นคอลัมน์ "Dose หาย" ในตาราง), fx สะสม, กราฟ TDF ตามวัน และจำนวน fraction ที่ต้องฉายเพิ่มใน course สุดท้ายเพื่อให้ถึง TDF เป้าหมาย |
|  | **แบบวันที่** (ค่าเริ่มต้น): กรอกแผนการฉายครั้งเดียว (Gy/fx, N รวม, fx/สัปดาห์, *เริ่มฉาย*) แล้วกด **+ เพิ่มช่วงพัก** กี่ช่วงก็ได้ (*เริ่มพัก*–*พักเสร็จ*, R นับรวมวันแรกและวันสุดท้าย) → ระบบแบ่งเป็นช่วงฉายตามช่วงพัก นับจำนวน fraction ของแต่ละช่วงจากปฏิทิน (5–7 ครั้ง/สัปดาห์เริ่มวันจันทร์ น้อยกว่านั้นยึดวันในสัปดาห์ของวันเริ่มฉาย; แก้จำนวนเองได้เมื่องดฉาย) ช่วงสุดท้ายได้ fraction ที่เหลือจาก N รวม พร้อมวันฉายครบ และคิด decay factor ทีละช่วงด้วยเวลาตามปฏิทินจริง · *แบบจำนวนวัน*: แยกหลาย course (dose ต่างกันได้) และกรอกจำนวนวันพักเอง |
| | **เพิ่ม fraction ชดเชย** (ต้องเลือก): *เพิ่ม* → กรอกจำนวน fraction ที่เพิ่ม (dose/fx และ fx/สัปดาห์) แล้ว TDF รวมคิดรวม fraction ที่เพิ่ม · *ไม่เพิ่ม* → ไม่ต้องกรอก ระบบแสดงจำนวน fraction ที่แนะนำเพื่อให้ถึง TDF เป้าหมายเสมอ |
| **Brachytherapy** | LDR dose rate คงที่ และแหล่งรังสีที่สลายตัว (I-125, Pd-103, Cs-131, Au-198, Ir-192, Cs-137, Co-60 หรือกำหนด half-life เอง) ทั้ง permanent และ temporary implant พร้อมกราฟ dose rate และ TDF สะสม |
| **สูตร & ตาราง** | สูตรทั้งหมดและตาราง TDF ต่อ fraction |

แถบ **ผู้ป่วยและแพทย์ผู้รักษา** (ใช้ร่วมกันทุกแท็บ, **บังคับกรอกทุกช่อง** ก่อนบันทึก recheck หรือสร้าง PDF): HN, คำนำหน้าชื่อ (มี "อื่น ๆ / ไม่มี"), ชื่อ, นามสกุล และแพทย์ผู้รักษา
(รายชื่อแพทย์อยู่ใน `PHYSICIANS` ใน `index.html`)

### สิทธิ์ตามตำแหน่งใน Workspace

| ตำแหน่ง | ทำได้ |
|---|---|
| **MP** (นักฟิสิกส์การแพทย์) | กรอกค่า คำนวณ บันทึกไว้ก่อน, เป็นผู้คำนวณหรือผู้ recheck (นักฟิสิกส์คนที่ 2), ลบรายการรอ recheck ของตัวเอง, เก็บ PDF ลง Drive |
| ตำแหน่งอื่น (RO, RTT, Nurse, …) | **ดูได้อย่างเดียว** — ช่องกรอกทั้งหมดถูกล็อก (แสดงขอบเส้นประ) และซ่อนปุ่ม "บันทึกไว้ก่อน" / "Recheck" / "ผู้ป่วยใหม่" แต่เปิดดูรายการคำนวณ ค่า ผล กราฟ และดาวน์โหลด PDF ที่ recheck แล้วได้ |

`Code.gs` ตรวจสิทธิ์ซ้ำที่ฝั่ง server (`tdfSave`, `tdfRecheck`, `tdfSavePdf`, `tdfWithdraw` รับเฉพาะ MP) จึงเลี่ยงผ่านหน้าเว็บไม่ได้ · เวอร์ชันเว็บธรรมดา (ฉบับร่าง ไม่ผ่าน Apps Script) ยังกรอกได้ตามปกติ

### Recheck โดยนักฟิสิกส์การแพทย์คนที่ 2 ที่หน้าจอ (บังคับ)

1. นักฟิสิกส์คนที่ 1 (เข้าสู่ระบบอยู่ = ผู้คำนวณ) กรอกข้อมูลผู้ป่วย แพทย์ และค่าที่ใช้คำนวณ
2. **ถ้าผู้ recheck ยังไม่อยู่:** กด **บันทึกไว้ก่อน** → บันทึกลง Google Sheet "TDF Calculator Records" สถานะ *รอ recheck* (บันทึกการคำนวณเดิมซ้ำไม่สร้างแถวใหม่)
   ปุ่ม "รายการคำนวณ" แสดงป้าย **รอ recheck N** · ตัวกรอง "รอ recheck" แสดงเฉพาะรายการที่รอ · ผู้คำนวณกด "ลบ" รายการที่รอของตัวเองได้
3. **เมื่อผู้ recheck มา:** กด **Recheck** (หรือ "Recheck" ที่รายการในรายการคำนวณ ซึ่งเปิดการคำนวณนั้นกลับมาบนหน้าจอให้)
   แผง **Recheck โดยนักฟิสิกส์การแพทย์คนที่ 2** แสดงว่าเป็นรายการที่บันทึกไว้ (เลขที่ เวลาบันทึก) หรือการคำนวณบนหน้าจอ พร้อมผู้คำนวณ ผู้ป่วย ชนิดการคำนวณ TDF และสรุป (อัปเดตตามหน้าจอทันที)
4. ผู้ recheck ตรวจค่าบนหน้าจอ กรอก **ชื่อผู้ใช้ (หรืออีเมล) และรหัสผ่าน LPCH RO Workspace ของตนเอง** ติ๊กยืนยันว่าตรวจสอบแล้ว แล้วกด **Recheck**
   ใช้ได้ทั้งที่เครื่องของผู้คำนวณ และที่เครื่องของผู้ recheck เอง (เข้าสู่ระบบด้วยบัญชีตนเองแล้วเปิดรายการที่รอ)
5. `Code.gs` ตรวจบัญชีนั้นกับ Workspace (`login` แล้ว `logout` ทันที ไม่เก็บรหัสผ่าน) ต้องเป็นตำแหน่ง **MP** และ**ไม่ใช่ผู้คำนวณ**
   - มีรายการที่บันทึกไว้ของการคำนวณเดียวกัน → แก้แถวนั้นเป็น *Recheck แล้ว* (ผู้คำนวณคงเดิม)
   - ไม่มี → บันทึกแถวใหม่สถานะ *Recheck แล้ว* โดยผู้คำนวณคือผู้ที่เข้าสู่ระบบอยู่
   การคำนวณที่ recheck แล้ว บันทึกหรือ recheck ซ้ำไม่ได้
6. หน้าเว็บสร้าง **รายงาน PDF** (A4 จัดตามชนิดการคำนวณ ขึ้นหน้าใหม่ระหว่างหัวข้อเท่านั้น มีเลขหน้า) ดาวน์โหลดให้ และ **เก็บลง Google Drive อัตโนมัติ**
   ในโฟลเดอร์ `TDF Reports (อนุมัติแล้ว)/<ปี-เดือน>` ชื่อไฟล์ `Decay Dose_<HN>_<ปปปป-ดด-วว>_<ชชนน>.pdf` (วันเวลาที่คำนวณ) ใน Drive ของบัญชีที่ deploy และบันทึกลิงก์ในชีต (คอลัมน์ `pdfFileId`, `pdfUrl`)
   รายงานมีโลโก้ ข้อมูลผู้ป่วย ผลคำนวณ ผล recheck และช่องลงชื่อ 3 ช่อง · ในรายการคำนวณมีปุ่ม "เปิดใน Drive" ถ้าเก็บไม่สำเร็จ กด "PDF + เก็บลง Drive" เพื่อลองใหม่ได้

ชีตใช้คอลัมน์เดิม (สถานะ `pending` = รอ recheck, `approved` = recheck แล้ว, คอลัมน์ `review…` = ผู้ recheck) · รายการรอ recheck จากระบบก่อนหน้า recheck ด้วยวิธีใหม่ได้เลย
การเขียนชีตและการสร้างโฟลเดอร์ใน Drive ทุกครั้ง (บันทึก, recheck, เก็บ PDF, ลบ, สร้างชีตครั้งแรก, เพิ่มหัวคอลัมน์ใหม่) ทำภายใต้ `LockService` (script lock) จึงไม่ชนกันเมื่อหลายคนใช้พร้อมกัน ถ้ารอคิวเกิน 20 วินาทีจะแจ้งให้ลองใหม่เป็นภาษาไทย การอ่านรายการไม่ต้องรอ lock
ก่อน deploy ครั้งแรก (และหลังอัปเดตที่เพิ่มการเก็บ PDF) ให้เลือกฟังก์ชัน `setup` แล้วกด Run หนึ่งครั้ง เพื่ออนุญาตสิทธิ์ Sheets และ Drive

เวอร์ชันเว็บธรรมดา (ไม่ผ่าน Apps Script) ใช้ได้เป็น *ฉบับร่าง* เท่านั้น: เก็บในเบราว์เซอร์ และ PDF มีแถบ "ฉบับร่าง"
